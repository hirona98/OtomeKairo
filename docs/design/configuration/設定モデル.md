# 設定モデル

## 基本前提

OtomeKairo では、人格設定、記憶、モデルプリセット、アバター音声、CocoroConsole端末設定、方針に関する設定の正本を本体側に置く。
外部接点はそれらを読む、選ぶ、変更要求を送ることはできるが、正本にはならない。

設定の永続正本は `config.db` に置く。
記憶、events、cycle trace、world_state、activity_state は `memory.db` に置く。
設定定義を `memory.db` に保存しない。

ここでいう設定とは、OtomeKairo が現在どう動くかを決める `現在設定` と、その選択対象になる `設定定義` を含む。
状態のように自然変化するものではなく、明示操作で変える本体条件として扱う。
現在の個そのものは設定ではなく、人格設定と記憶からその都度成立する判断主体として扱う。
`drive_state` のような派生内部状態も設定ではなく状態として扱う。

## 設定の層

設定は、少なくとも次の 2 層に分ける。

- 現在設定
  - 現在の選択値と方針
- 設定定義
  - 選択対象となる定義本体

## 現在設定

現在設定は、OtomeKairo がいまどういう設定で動くかを表す。
ここには少なくとも次の系統を含める。

- 現在選択中の人格設定
- 現在選択中の記憶集合
- 現在選択中のモデルプリセット
- 送信前チェックで使用するモデルプリセット
- 現在選択中のアバター音声プリセット
- 保存音声入力元（OtomeKairo、CocoroConsole、ブラウザ）、ローカルdevice、CocoroConsole clientとdevice、VAD、話者識別の設定
- 会話入力で使用する `conversation_display_name` 定義の選択ID
- 観測源ごとの有効化と取得方針
- 自律判断機会の付与方針
- 気にかけていること（`standing_concerns`）。意味境界は [../runtime/気にかけていること.md](../runtime/気にかけていること.md) を正とする

ここで重要なのは、「長く残るもの」ではなく「明示操作で変える現在条件」を設定に入れることだ。
保存期間の長さではなく、意味上いま何を使うか、どう動くかを優先する。

## 設定定義

設定定義は、現在設定の選択値が指す定義本体である。
少なくとも次を含む。

- `persona`
  - 持続的な人格設定の定義
  - `persona_prompt`、`initiative_baseline`、`expression_addon`、`wake_words` を含む
  - `wake_words` は通常音声入力を会話入力へ進める prefix 一覧であり、LLM の `persona_context` には入れない
- `memory_set`
  - 人格設定と独立に選べる記憶全体の単位
  - 記憶検索と記憶更新に使う埋め込み設定もここに持つ
  - 埋め込み設定は `model`、`api_base`、`api_key`、`embedding_dimension` を含む
- モデルプリセット（`model_preset`）
  - 全生成処理で共有するモデルと接続定義
  - 直近会話候補の取得窓もここに含める
- アバター音声プリセット（`avatar`）
  - アバターに対応する音声合成と音声認識の設定定義
  - 音声合成の有効/無効、engine、VOICEVOX 系、Style-Bert-VITS2、Aivis Cloud の設定を含む
  - VOICEVOX 系は優先 endpoint とサブ endpoint（空可）を持ち、接続先選択の実行境界は [../api/event_stream.md](../api/event_stream.md) を正とする
  - 音声認識の有効/無効、AmiVoice の Profile ID、API key を含む
  - 音声起動ワードは人格設定側の `wake_words` を使う
  - VRM、表示、モーションは `client_id` ごとのCocoroConsole端末設定から参照する
  - 人格設定と人物の定義から独立した設定として扱う
  - 利用先を音声入出力処理に限定し、LLM context は人格設定、記憶、現在入力から構築する
- 音声人物（`voice_speaker`）
  - 音声入力で識別する人物の `person_ref`、`conversation_display_name_id`、登録状態、話者 embedding、model metadata を含む
  - 表示名は参照先の `conversation_display_name` 定義から解決する
  - 話者 embedding は設定 API と inspection へ返さない
  - 音声登録解除後も人物 row と `person_ref` を維持する
  - 人物について形成した記憶と関係は `memory.db` に置き、音声人物設定へ複写しない
- カメラ source 定義（`camera_source`）
  - OtomeKairo の視覚として採用する camera source の定義
  - `display_name`、connector の `client_id`、有効/無効を含む
  - `display_name` は人間向け名と LLM へ渡す source metadata の正本である
  - `vision_source_id` と `watcher.watcher_id` は `display_name` から生成する
  - 接続先 host と camera account を含む
  - camera account は connector ではなく OtomeKairo 本体が保持する
  - RTSP / ONVIF / PTZ の詳細値は connector 実装の既定値として扱う
- MCP server 定義（`mcp_server`）
  - 汎用 MCP client connector が接続する MCP server の定義
  - `mcp_server_id`、connector の `client_id`、有効/無効、transport と transport 固有接続値を含む
  - `transport=stdio` は `command / args / cwd / env`、`transport=streamable_http` は `url / headers` を持つ厳格な tagged union とする
  - 実行可否の正本は MCP server の有効/無効であり、接続中 `tools/list` catalog の tool を利用できる
  - `mcp_server_id` は接頭辞なしの名前であり、設定内で一意にする
  - MCP server の API key や token は `env` または `headers` の設定値として OtomeKairo 本体が保持する
  - `pre_send_check_enabled` は当該 server の全 tool call を dispatch 前の送信前チェック対象にする
  - 読み取り中心の MCP は `false`、投稿や外部書き込みを含む MCP は `true` を選ぶ
  - MCP tool の description と input schema は接続時の runtime metadata として扱い、設定定義の正本にしない
  - `autonomous_session` は任意の MCP server で使える有限セッションの開始可否、background 開始可否、最短間隔、tool call 上限を持つ。実行契約は [../runtime/autonomous_run.md](../runtime/autonomous_run.md#有限-mcp-セッション) を正とする
  - `inbound_observation` は任意の MCP server で使える、届いている働きかけの有無を見る観測方針である。設定 wire は [../api/状態と設定.md](../api/状態と設定.md)、意味境界は [../llm/mcp_inbound_observation.md](../llm/mcp_inbound_observation.md) を正とする
  - 既定状態は disabled の `elyth` と `e-stat` 定義をこの順で持つ
  - 既定の `elyth` 定義は Streamable HTTP の設定例として endpoint、空の `Authorization`、enabled の有限セッション方針を持つ。MCP server 自体は disabled とし、有効化前に認証値の明示入力が必要である
  - 既定の `e-stat` 定義は stdio の設定例として `pre_send_check_enabled=false`、空の `E_STAT_APP_ID`、disabled の有限セッション方針を持ち、秘密値を含まない
- Agent Skill source 定義（`agent_skill_source`）
  - 外部 Agent Skills root の `source_id / enabled / root_path / script_execution` を保持する
  - `source_id` は source の名前であり、別の表示名は持たない
  - `script_execution` は script 実行を許すかの `enabled` だけを持つ。interpreter と資源上限は runner 固定であり設定に含めない
  - package の発見、LLM 選択、resource 読込、script 信頼境界は [Agent Skills 統合](../integration/AgentSkills統合.md) を正本とする
  - 既定状態は disabled の `elyth-skills` 定義を持つ
  - 既定の `elyth-skills` は配置例として `root_path=/opt/elyth-remote-mcp-skills/skills` と `script_execution.enabled=false` を持つ。source 自体は disabled とし、有効化前に repository の checkout と script 信頼確認を求める
  - skill package 本体は repository 内へ vendoring しない
- CocoroConsole端末設定（`console_client_settings`）
  - `client_id` ごとに表示、ローカルprocess、デスクトップ取得、VRM表示、モーションを保持する
  - `process` は `console_api_port` と `cocoro_shell_port` だけを持ち、対話入力の有効/無効は持たない
  - `avatar_presentations[].model` はCocoroConsoleが選択したモデル指定値を保持する
  - OtomeKairoはモデル指定値を組み込みモデルとVRMファイルに分類せず、値の解決と存在確認を行わない
  - モニター座標とウィンドウ位置は端末固有値としてOtomeKairoに保存する
  - VRMやアニメーションのファイル実体、話者識別用の音声埋め込みは含めない
  - `last_connected_at` はWeb UIが最後に接続した端末を選ぶための配送metadataであり、端末設定本文には含めない
  - CocoroShellは設定の正本を持たず、CocoroConsoleが選択済みの端末設定を起動時設定へ変換して配送する
  - CocoroShellの起動時設定にSTT設定、TTS設定、音声providerの資格を含めない
  - CocoroShellは起動時設定をメモリ上だけに保持し、設定変更はCocoroShellの再起動で反映する
  - 配送wireと位置保存の契約は[../api/状態と設定.md](../api/状態と設定.md#cocoroshellへの実行時設定配送)を正とする
- デスクトップ取得方針既定（`desktop_capture_defaults`）
  - 一度も CocoroConsole が connect していない間の `desktop_capture` を保持する
  - 初回 connect で新規端末設定を作るとき、初期 `desktop_capture` として使う
  - 既存端末の `desktop_capture` を自動では上書きしない
  - 思考前デスクトップ観測 on/off 自体は `wake_policy.observations` に置き、接続有無に依存せず編集できる
  - `vision.capture_request` の配送は接続中の desktop vision source があるときに限る

これらは「現在どれを選んでいるか」という現在設定そのものではない。
現在設定と設定定義を分けることで、同じ定義群の中からいま使うものだけを切り替えられる。

`memory_set` は人格設定に従属しない。
同じ人格設定に対して複数の `memory_set` を持つ。
同じ `memory_set` を異なる人格設定と組み合わせて選ぶ。

## 会話入力と音声話者で共有する呼ばれ方

`conversation_display_name` は完成済みの呼び名を複数保持する設定定義である。
各定義は不変の `conversation_display_name_id` と、重複しない `display_name` を持つ。
会話入力の現在設定は `selected_conversation_display_name_id` で定義を1件選択する。
CocoroConsoleとブラウザの直接入力は、選択した定義の `display_name` を
`interaction_context.participants[].display_name` に設定する。

`voice_speaker` は独自の名前を持たず、`conversation_display_name_id` で同じ定義群の1件を参照する。
1件の呼ばれ方を複数の音声話者へ割り当てない。
話者登録時は未割当の呼ばれ方を選択し、登録処理にはIDだけを渡す。
音声認識で話者を識別した入力は、話者が参照する定義の `display_name` を使用する。
この表示名は人物文脈としてLLM入力へ渡る。話者embeddingと話者登録用の内部値はLLM入力へ渡さない。

表示名の変更は参照先すべてへ即時反映する。
呼ばれ方定義は1件以上を保ち、会話入力の選択は常に存在する定義を指す。
会話入力で選択中の定義を削除するとき、残りの定義の1件へ選択を付け替える。
音声話者が参照している定義と、最後の1件は削除しない。
新規既定状態は `display_name=マスター` の呼ばれ方定義を1件持ち、会話入力の選択もその定義にする。
Web UI は設定画面でこれらを「呼ばれ方」と表示する。
Web UI の対話入力面には「呼ばれ方」を常時表示せず、選択中定義の表示名を会話入力へ使う。
人物同一性や対象選択は `person_ref` と `response_target_refs` で扱う。
Web UI と CocoroConsole は `person_ref` と `interaction_ref` を対話入力面へ表示せず、
それぞれの外部接点が内部で確定して API へ渡す。

## CocoroConsoleの接続用情報

CocoroConsoleがOtomeKairoへ接続する前に必要な `server_url`、`client_id`、
`console_access_token` はCocoroConsoleの `Connection.json` に置く。
これらは通常設定ではなくbootstrap情報であり、CocoroConsole端末設定に含めない。
CocoroConsoleはOtomeKairo processを起動せず、外部serviceへ接続する。

## 選択値

選択値は、現在設定のうち「現在どれを使うか」を表す部分である。

少なくとも次を持つ。

- 選択中の人格設定
- 選択中の記憶集合
- 選択中のモデルプリセット
- 送信前チェック用のモデルプリセット
- 選択中のアバター音声プリセット

選択値は、定義本体のコピーではなく参照である。

## 現在設定と状態

選択値は現在設定に置く。
設定された内容は、そのまま現在有効な条件として扱う。

一方で、状態側の実行状態は、接続状態や進行中の行動のような稼働状況だけを持つ。
設定の選択値を別名で重複保持する場所にはしない。

たとえば人格設定、記憶、モデルプリセットは、選択された時点で現在使っている設定として扱う。

## 設定定義の種類

人格設定、記憶集合、モデルプリセットはすべて設定定義だが、役割は同じではない。

- 人格設定
  - 持続的な姿勢、自発傾向、判断傾向を与える
- 記憶集合
  - どの経験蓄積全体を現在の個の構成要素として使うかを決める
  - その集合に対応する埋め込み設定も持つ
- モデルプリセット
  - 全生成処理をどのモデル定義で支えるかを決める
- アバター音声プリセット
  - 発話本文の生成後に使用する音声合成と、対話入力本文の生成前に使用する音声認識を決める
  - 音声合成設定は OtomeKairo の TTS runtime が使用する
  - 音声認識設定は OtomeKairo の音声入力 runtime が使用する

一方で、観測や自律判断の方針は `persona` のような選択対象ではなく、現在設定に直接入る項目として扱う。
`thinking_speech_level` は、`background_thinking` の各判断で短い独話として前へ出る自然さを見積もるときの補助レベルを表す現在設定である。
値は `1..10` の整数で、`1` は控えめ、`5` は標準、`10` は短い独話としてまとまる場合に前へ出やすい基準を表す。
既定値は `5` である。
定期思考処理は `enabled=true` の `camera_source` を実行時に観測対象へ含める。
`camera_source` の更新は `wake_policy.observations` を書き換えない。

`memory_set` は、空の集合として新規作成するか、既存の `memory_set` 全体を複製して作成する。
`memory_set` の削除は、集合全体を対象にする設定定義削除として扱う。
個別の `event`、`episode`、`memory_unit`、感情記録、派生状態を設定操作として確認、承認、訂正、撤回、削除しない。
`memory_set` の初期化と export は提供しない。

人格設定の詳細は [人格設定詳細.md](人格設定詳細.md)、モデルプリセットの詳細は [モデルプリセット詳細.md](モデルプリセット詳細.md) を正とする。

## 設定に含めないもの

次は、設定と混同しない。

- 外界の現在位置や一時的な接続可否
- 実行中かどうかの稼働状態
- `drive_state` のような中期内部状態
- 保留意図のような短期内部状態
- クライアントのローカル編集状態
- デバッグ表示用の派生要約

設定は「明示操作で変える本体条件」であり、自然変化するものや表示都合のものは含めない。
