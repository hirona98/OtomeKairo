# モデルプリセット詳細

## 基本前提

OtomeKairo は、通常の生成処理で選択中の同じモデルプリセットを使う。
論理 role はプロンプト、入力文脈、構造化出力契約、trace の責務境界として維持し、モデル割り当てには使わない。
埋め込みモデルは生成モデルと用途が異なるため、`model_preset` に含めず `memory_set.embedding` に置く。

外部送信の独立した安全境界である `outbound_content_review` だけは、現在設定の `outbound_content_review_model_preset_id` が指すモデルプリセットを使う。
この選択は通常生成の `selected_model_preset_id` と独立し、同じ定義を指してもよい。

複数のモデルプリセットを設定定義として保持し、`selected_model_preset_id` で現在使う 1 件を選択する。
モデルプリセットの切り替えは人格設定と記憶集合を変更しない。

## 論理 role

生成処理は次の論理 role に分かれる。

| role | 主な責務 |
|------|------|
| `input_interpretation` | 入力、想起入口、`world_state` 候補抽出を整理する |
| `recall_pack_selection` | `RecallPack` 候補の配置、採用、競合要約を決める |
| `event_evidence_generation` | 選択済み `event` 群から短い根拠表現を作る |
| `pending_intent_selection` | eligible な保留候補から今扱う 1 件または `none` を決める |
| `decision_generation` | 何をするべきかを判断する |
| `autonomous_step_generation` | `autonomous_run` の次の action と transition を決める |
| `expression_generation` | 決定済み内容を外向きの表現へ変換する |
| `outbound_content_review` | 外部 MCP へ送る最終 payload の開示可否を判定する |
| `memory_interpretation` | 記憶更新や再整理に必要な解釈を行う |
| `memory_correction_reconciliation` | 訂正らしさと対象 revision を照合する |
| `memory_reflection_summary` | `reflective consolidation` の要約文を生成する |

`visual_observation`、`world_state`、`activity_state`、`initiative_entry_check` も専用モデル設定を持たず、選択中のモデルプリセットを使う。

## モデルプリセット構造

モデルプリセットは次の構造を持つ。

```yaml
model_preset_id: model_preset:default
display_name: Default OpenRouter Gemini Preset
prompt_window:
  recent_turn_limit: 30
  recent_turn_minutes: 30
model: openrouter/google/gemini-3.1-flash-lite-preview
api_key: ""
max_output_tokens: 4000
timeout_seconds: 90
web_search_enabled: false
```

`api_base` と `reasoning_effort` は任意項目である。
`api_base` が未指定のときは、`model` の先頭から導ける既定の接続先を使う。
`reasoning_effort` が未指定のときは provider と model の既定動作を使う。

`prompt_window.recent_turn_minutes` は判断サイクルで取得する直近会話候補の時間窓、`prompt_window.recent_turn_limit` は件数上限である。
`RecallHint` と保留意図選別は、この候補集合から各機能の入力制約に従って発話を選ぶ。

## 生成request

`model`、`api_base`、`api_key`、`reasoning_effort`、`max_output_tokens`、`timeout_seconds`、`web_search_enabled` は、選択中プリセットを使う全生成requestへ共通に適用する。

`provider` は独立項目として持たない。provider は `model` の先頭部分から導く。
`timeout_seconds` は1以上の整数で指定する生成request 1 回あたりのtransport timeoutである。
timeoutは通常のLLM failureとして扱い、対応するcycle traceとauditへ残す。

`web_search_enabled` はprovider側の検索機能を有効化する通過設定であり、OtomeKairoのcapabilityではない。
有効時は会話、判断、視覚解釈、記憶処理、background処理を含む全生成requestへ適用する。
provider側検索の内部過程は観測eventとして保存しない。

## 秘密値

`api_key` はモデルプリセットの一部として保持する。
通常の読み取り、ログ、inspection、cycle traceでは実値を返さない。
認証済み設定編集bundleだけが実値を扱う。

## 更新

モデルプリセットの更新、選択、削除は別の設定操作として扱う。
更新は定義全体を検証してから正本へ反映し、部分的に壊れた定義を保存しない。
変更単位は [設定変更.md](設定変更.md)、API wireは [../api/状態と設定.md](../api/状態と設定.md)、資格情報の境界は [../integration/接続と権限境界.md](../integration/接続と権限境界.md) を正とする。
