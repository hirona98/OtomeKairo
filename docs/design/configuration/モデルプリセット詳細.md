# モデルプリセット詳細

## 基本前提

OtomeKairo は、通常の生成処理で選択中の同じモデルプリセットを使う。
論理 role はプロンプト、入力文脈、構造化出力契約、trace の責務境界として維持し、モデル割り当てには使わない。
埋め込みモデルは生成モデルと用途が異なるため、`model_preset` に含めず `memory_set.embedding` に置く。

外部送信の独立した安全境界である `pre_send_check` だけは、専用の固定モデルプリセット `model_preset:pre_send_check` を使う。
現在設定の `pre_send_check_model_preset_id` は常にこの ID を指し、通常生成の `selected_model_preset_id` と共有しない。
editor-state の `model_presets` にこの専用定義が無い場合は拒否する。別プリセットから作らない。
Web UI の送信前チェックタブで、この専用定義の接続設定（model / api_base / api_key など）を直接編集する。
生成用モデルタブのプリセット一覧には専用定義を出さない。

複数の生成用モデルプリセットを設定定義として保持し、`selected_model_preset_id` で現在使う 1 件を選択する。
モデルプリセットの切り替えは人格設定と記憶集合を変更しない。

## 論理 role

生成処理は次の論理 role に分かれる。

| role | 主な責務 |
|------|------|
| `input_interpretation` | 入力、想起入口、`world_state` 候補抽出を整理する |
| `recall_pack_selection` | `RecallPack` 候補の配置、採用、競合要約を決める |
| `event_evidence_generation` | 選択済み `event` 群から短い根拠表現を作る |
| `pending_intent_selection` | eligible な保留候補から今扱う 1 件または `none` を決める |
| `decision_generation` | 何をするべきかを判断する |
| `autonomous_step_generation` | `autonomous_run` の次の action と transition を決める |
| `expression_generation` | 決定済み内容を外向きの表現へ変換する |
| `pre_send_check` | 外部 MCP へ送る最終 payload の開示可否を判定する |
| `memory_interpretation` | 記憶更新、再整理、直近 revision の訂正対象選定に必要な解釈を行う |
| `memory_reflection_summary` | `reflective consolidation` の要約文を生成する |

`visual_observation`、`world_state`、`activity_state`、`initiative_entry_check` も専用モデル設定を持たず、選択中のモデルプリセットを使う。

## モデルプリセット構造

モデルプリセットは次の構造を持つ。

```yaml
model_preset_id: model_preset:default
display_name: Default OpenRouter Gemini Preset
prompt_window:
  recent_turn_limit: 30
  recent_turn_minutes: 30
model: openrouter/google/gemini-3.1-flash-lite
api_key: ""
max_output_tokens: 32000
timeout_seconds: 90
web_search_enabled: false
```

`api_base` と `reasoning_effort` は任意項目である。
`api_base` が未指定のときは、`model` の先頭から導ける既定の接続先を使う。
`reasoning_effort` が未指定のときは provider と model の既定動作を使う。

`max_output_tokens` の既定値は 32000 とし、推論と本文を合わせた出力予算の検証開始値として扱う。モデル自身の最大出力容量や入力 context window、本文文字数とは別の値である。推論モデルでは、内部の推論が出力予算を消費するため、短い本文でも予算不足になることがある。
設定する値は選択モデルと接続先が対応する最大出力上限以内にする。Web UI、設定 API、transport は明示指定された予算を正の整数として検証し、不正値を既定値や provider の既定動作へ置き換えない。モデル固有の対応上限は利用者が選択モデルの仕様で確認する。transport は値を自動で切り下げたり、上限超過時に増やして再送したりしない。対応上限を超えるなどの理由で provider が拒否した場合は明示失敗として扱う。
`reasoning_effort` を強くすると推論トークン数と所要時間が増えるため、出力予算と `timeout_seconds` を合わせて調整する。タイムアウトの既定値 90 秒は、全モデル・全推論設定での完了を保証する値ではない。
実運用では [生成使用量のログ](../runtime/デバッグ可能性.md#llm-生成使用量) の消費量、終了理由、所要時間を確認して調整する。Web UI は生成用と送信前チェック用の両方に、この予算の意味と調整方法を表示する。
内省要約や視覚説明の文字数上限は、保存する情報の用途ごとの契約であり、トークン予算から算出しない。正本は [内省要約のLLM生成](../memory/内省要約のLLM生成.md) と [vision_capture画像意味理解](../capability/vision_capture画像意味理解.md) とする。

`prompt_window.recent_turn_minutes` は判断サイクルで取得する直近会話候補の時間窓、`prompt_window.recent_turn_limit` は件数上限である。
`RecallHint` と保留意図選別は、この候補集合から各機能の入力制約に従って発話を選ぶ。

## 生成request

`model`、`api_base`、`api_key`、`reasoning_effort`、`max_output_tokens`、`timeout_seconds`、`web_search_enabled` は、選択中プリセットを使う全生成requestへ共通に適用する。
structured role の生成request には `json_schema` を付ける。載せ方と非対応時の失敗は [../llm/LLM構造化出力transport.md](../llm/LLM構造化出力transport.md) を正とする。
モデルプリセットに structured output の on/off は持たない。

`provider` は独立項目として持たない。provider は `model` の先頭部分から導く。
`max_output_tokens` は、provider が `openai` または `azure` の場合は LiteLLM に `max_completion_tokens`、それ以外は `max_tokens` として渡す。これは [OpenAI Chat Completions の出力上限パラメータ](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) に合わせた変換であり、モデル名の世代判定に依存しない。provider 固有の wire への変換は LiteLLM が担う。
`timeout_seconds` は1以上の整数で指定する生成request 1 回あたりのtransport timeoutである。
timeoutは通常のLLM failureとして扱い、対応するcycle traceとauditへ残す。

`web_search_enabled` はprovider側の検索機能を有効化する通過設定であり、OtomeKairoのcapabilityではない。
有効時は会話、判断、視覚解釈、記憶処理、background処理を含む全生成requestへ適用する。
provider側検索の内部過程は観測eventとして保存しない。

## 秘密値

`api_key` はモデルプリセットの一部として保持する。
通常の読み取り、ログ、inspection、cycle traceでは実値を返さない。
認証済み設定編集bundleだけが実値を扱う。

## 更新

モデルプリセットの更新、選択、削除は別の設定操作として扱う。
更新は定義全体を検証してから正本へ反映し、部分的に壊れた定義を保存しない。
変更単位は [設定変更.md](設定変更.md)、API wireは [../api/状態と設定.md](../api/状態と設定.md)、資格情報の境界は [../integration/接続と権限境界.md](../integration/接続と権限境界.md) を正とする。
