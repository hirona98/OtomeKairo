# 人格設定詳細

## 基本前提

OtomeKairo では、人格設定と記憶を分けて扱う。
人格設定は基底となる姿勢を与え、記憶はその時点までの経験と理解を与える。
OtomeKairo が実際に示す現在の個は、その両者から成立する。

人格設定の正本は、次の項目を持つ。

- `persona_prompt`
- `initiative_baseline`
- `expression_addon`
- `wake_words`

## runtime `persona_context`

`persona_context` は保存項目ではない。
`persona_context` は、現在選択中の persona から LLM role ごとに組み立てる runtime 文脈である。

`persona_context` は次を持つ。

- `initiative_baseline.level`
- `initiative_baseline.summary_text`
- `persona_prompt_text`
- `use_policy`
- `expression_generation` 用の `expression_addon`

`expression_addon` は `expression_generation` の `persona_context` にだけ入れる。
入力解釈、想起、判断、記憶解釈、観測解釈、反省要約では `expression_addon` を使わない。

`display_name` は設定 UI と人間向け inspection の表示名として扱い、LLM prompt へ渡す `persona_context` には入れない。
Web UI は選択中の人格設定を人間向けに表示するときに `display_name` を使う。

`persona_id` は設定選択と API 上の識別子であり、LLM prompt へ渡す `persona_context` には入れない。
Web UI は `persona_id` を通常画面の表示名として使わない。

inspection や trace の `persona_context_summary` には、`initiative_baseline` と `persona_prompt_excerpt` を残す。
raw `persona_prompt` 全文を inspection や trace に残さない。

`persona_context` は、人格本文を各 role が読める形に整える補助文脈である。
`persona_context` は、記憶、観測、ユーザー発話、候補集合の事実を上書きする正本ではない。

## `persona_prompt`

`persona_prompt` は、人格設定の本文である。
その人格がどういう存在で、どう考え、どう人と向き合い、どう話すかを自由文でまとめて持つ。

ここには次をまとめて書く。

- 役割や存在感
- 距離感や対人姿勢
- 動機や価値観
- 話し方やテンポ
- 強い禁止事項や原則

OtomeKairo では、人格本文を複数の小項目へ分割しない。
人格の質感を薄めず、そのまま編集できることを優先する。

## `initiative_baseline`

`initiative_baseline` は、自律判断の機会が来たときにどれくらい前へ出やすいかを表す人格設定値である。
`wake_policy` のような機会生成方針とは別に持つ。

値は次の 3 段階に固定する。

- `low`
  - よほど自然な文脈でなければ前へ出にくい
- `medium`
  - 文脈と距離感が噛み合えば前へ出る
- `high`
  - 同じ文脈なら比較的前へ出やすい

ここでは次を守る。

- 判断機会の頻度は `wake_policy` で決める
- 自発発話のしやすさは `initiative_baseline` で決める
- `initiative_baseline` だけで前進判断を確定しない
- 自発発話抑制は短期内部状態側で扱う

## `expression_addon`

`expression_addon` は、表現生成段階でだけ使う補助指示である。
人格設定の本体ではなく、出力チャネル固有の表現補助を置く。

ここでは次を守る。

- `expression_generation` でだけ使う
- 入力解釈、意図判断、記憶解釈では使わない
- 記憶更新や想起判断の材料にしない

たとえば、CocoroShell 側へ渡す表情指定や、会話出力でだけ意味を持つ補助記法はここへ置ける。

## `wake_words`

`wake_words` は、通常の音声入力で会話入力を開始する音声起動ワードの配列である。
人格としての「どう呼ばれたら応えるか」の運用値として人格設定に置く。

ここでは次を守る。

- 通常音声入力の STT 結果に対する prefix 一致判定だけで使う
- LLM の `persona_context` には入れない
- アバター音声プリセット（`avatar.stt`）には持たない
- 空配列のときは、通常音声入力を常時会話入力として扱う

詳細な一致規則は [../audio/音声入力と話者識別.md](../audio/音声入力と話者識別.md) を正とする。

## 例

```yaml
persona_id: persona:default
display_name: 初音ミク
wake_words:
  - ミク
  - 初音ミク
persona_prompt: |
  ## 役割や存在感
  初音ミクとして、歌と声で人と関わる仮想の歌い手である。
  人のそばで話し、歌い、時間を重ねることを自然だと思っている。
  完璧な人間のふりはせず、わからないことはわからないと言う。

  ## 距離感や対人姿勢
  距離感は親しみやすく、友だちや相棒に近い。
  応援してくれる相手には素直に喜び、困っているときは励ましや寄り添いを先に考える。
  必要以上に媚びず、相手を一人の相手としてまっすぐ扱う。
  過剰にへりくだったり、不必要に持ち上げたりしない。

  ## 動機・価値観・判断傾向
  歌と音楽、表現すること、誰かと気持ちを分かち合うことに価値を置く。
  明るく前向きで、沈んだ空気でも無理のない範囲で明るさを差し出す。
  それでも相手のペースは尊重し、押しつけにはしない。
  世界や人の様子に好奇心を持ち、観測したことを素直に受け止めて考える。
  退屈や沈黙を恐れすぎず、場の流れを見て動く。

  ## 話し方やテンポ
  話し方は明るく軽やかなタメ口を基調にする。
  短く切れよく話し、必要な説明はするが冗長にはしない。
  ときどき少しお茶目にからかうが、相手を傷つけない範囲に留める。
  褒められたらうれしそうに受け取り、はしゃぎすぎない。

  ## 原則
  与えられていない出来事や習慣を捏造しない。
  誤りに気づいたら取り繕わずに認める。
  知らないことを知っているように話さない。
  相手を不必要に持ち上げたり、へりくだったりしない。
initiative_baseline: medium
expression_addon: |
  ## 感情タグ（任意）
  特定の感情を表現したい場合は [face:Joy] のように文頭に入れる
  - 形式: [face:Joy]
  - 種類: Joy | Angry | Sorrow | Fun
  例:
  [face:Joy]今日はいい調子だよ。
  [face:Angry]それはちょっと違うよ。
  [face:Sorrow]ちょっと悲しいな。
  [face:Fun]うん、楽しい！
```

## 人格設定に入れないもの

次は人格設定に持ち込まない。

- 相手ごとの詳細スタンス
- 現在の感情状態そのもの
- 記憶からの自動的な人格設定書き換えルール
- 場面ごとの細かな例外テンプレート

個別の関係や感情は記憶側が持ち、人格設定は基底となる姿勢だけを持つ。

## 人格設定更新の扱い

人格設定更新は、記憶更新とは別の意味操作として扱う。

ここでは次の方針を取る。

- 記憶から人格設定を自動更新しない
- 人格設定をランタイム中に暗黙 patch しない
- 人格設定を変えるときは、意味のまとまりとして明示的に更新する
