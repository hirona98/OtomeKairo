# 人物と相互作用

## 正本境界

この文書は、一つの OtomeKairo が複数の人物と関わるときの意味境界を定める。
HTTP の wire shape は [../api/bootstrapと入力.md](../api/bootstrapと入力.md)、記憶の保存形は [../memory/データモデル.md](../memory/データモデル.md) を正とする。

## 一つの個

選択中の人格設定と記憶集合から成立する OtomeKairo は、一つの判断主体である。
人物ごとに OtomeKairo のインスタンス、人格設定、記憶集合を分割しない。
気分、drive、自己理解は個に属し、人物モデル、関係、人物の短期活動状態は人物参照ごとに分ける。

## 外部人物識別

テキスト入力と外部サービス入力の人物識別は OtomeKairo の外部で完了させる。
OtomeKairo はそれらの API で受けた `person_ref` を確定済みの安定識別子として使用する。
OtomeKairo は `person_ref` と認証主体の対応確認、なりすまし検出、表示名からの同一人物推定を実行しない。
接続 connector は、外部サービスの認証済み主体を安定した `person_ref` へ変換する責任を持つ。

connector は `person_ref` とともに、人間向けの非空 `display_name` を渡す。
`display_name` は、その入力で人物を表示し、内部自然文で示し、外向き発話で直接呼ぶ場合に使う完成済みの呼び名である。
connector は敬称を含む実際の呼称を `display_name` に入れ、OtomeKairo は文字列全体を変更せずに使う。
人物同一性、対象選択、配送先は `person_ref` で確定し、`display_name` を根拠にしない。
呼び名の管理方法は connector が決定し、OtomeKairo にテキスト入力人物の管理機能を設けない。

MCP tool 結果に現れる外部主体も、同じ境界で connector が識別を完了する。
connector は閉じた object key `actor` と `author` だけを見る。各 object に非空の `handle` と `display_name` があるとき、`person_ref=person:mcp:<mcp_server_id>:<handle>` と、その `display_name` をそのまま `client_context.observed_persons[]` へ入れる。
OtomeKairo は受け取った `observed_persons` を確定済み参照として使い、表示名や本文から同一人物を推定しない。
`observed_persons` は関連人物の `people_context` と記憶の人物参照に使う。会話の `speaker_ref` や配送先にはしない。

音声入力はこの外部人物識別境界の例外とする。
OtomeKairo は登録済み話者 embedding と発話音声を照合し、`person:voice:<UUID>` を確定する。
音声人物の表示名、embedding、登録状態は OtomeKairo の `config.db` を正本にする。
音声人物の識別、登録、相互作用参照は [../audio/音声入力と話者識別.md](../audio/音声入力と話者識別.md) を正とする。

## 相互作用文脈

各入力は次を区別する。

- `interaction_ref`: 会話履歴と非同期応答を結ぶ論理的な場
- `speaker_ref`: 現在の発話者
- `participants`: 現在の相互作用に参加する人物

初期実装は人物1名との1対1相互作用だけを受理する。
`participants` は配列として保持し、複数人会話を追加するときに wire 全体を作り直さない。
会話履歴は `memory_set_id / interaction_ref` で読み、別の場の直近発話を混ぜない。

## 人物別状態

人物についての理解は `scope_type=entity / scope_key=person:*` に保存する。
関係は `scope_type=relationship / scope_key=self|person:*` に保存する。
人物の短期活動状態は `actor_ref=person:*` ごとに1件を持つ。
現在の機嫌、drive、自己状態は OtomeKairo 自身の全体状態として保持する。

定期思考には、選択済み記憶、関係、約束、保留意図、自律実行に構造化された `person_ref` だけを関連人物として渡す。
関連人物は `people_context[].person_ref / display_name` で表し、自然文の解析や表示名の一致で選ばない。
定期思考には単一の「現在の会話相手」を設定しない。
内部判断の人物対象は `person_ref` で固定し、説明文で人物名が必要な場合だけ対応する `display_name` を使う。

## 記憶の出所と開示

会話由来の event、episode、memory unit は、元の `interaction_ref` と参加人物参照を構造化された provenance として保持する。
選択済み記憶に応答対象人物以外の provenance が含まれ、発話を生成した場合だけ `disclosure_review` を実行する。
レビューは候補発話を許可、書き換え、見送りのいずれかへ確定する。
レビューの生成または契約検証に失敗したサイクルは内部失敗とし、未レビューの候補発話を返さない。
trace にはレビュー結果、理由コード、対象の記憶または episode の参照だけを残し、他者の私的本文を監査要約へ複写しない。

## サイクル調停

会話入力、手動 wake、通常および autonomous run の非同期 capability result は、一つの個に対して FIFO で直列実行する。
これらのサイクルが実行中または待機中なら、その周期の定期思考と due autonomous run を開始しない。
会話がない時間の定期思考は従来どおり実行する。
この調停は通常会話へ追加の LLM 呼び出しを発生させない。

## 非同期応答

非同期処理は起点の `requested_by_person_ref / origin_interaction_ref / participant_refs` を保持する。
人物へ向けた外向きの `assistant_message` は `interaction_ref / recipient_person_refs` を必須の論理配送先として持つ。
`target_client_id` は connector への物理配送先であり、人物や会話の意味を表さない。
人物へ向けた発話で論理配送先または起点 connector が確定しない場合は、外部へ配送しない。
購読 client が1件だけという理由で配送先を補完しない。

`wake / background_thinking` が相手の反応を前提としない独話を選んだ場合は、人物への発話ではなく周囲への独話として扱う。
周囲への独話は `interaction_ref=null / recipient_person_refs=[]` を明示し、人物や直近の相互作用を補完しない。
本文は `assistant_message` の購読 client、音声は現在設定の音声出力先へ配送する。
この例外は `wake / background_thinking` だけに適用し、会話応答、人物起点の capability result、自律実行の人物向け発話には適用しない。
