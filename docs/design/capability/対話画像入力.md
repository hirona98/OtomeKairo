# 対話画像入力

## 目的

通常会話 API が、`text` と `client_context` だけでなく会話添付 image payload も受け取る。

元画像を [入力解釈](../llm/入力解釈.md) と当回の行動判断へ渡し、詳細説明を想起と記憶整理に使う。
会話添付画像は `vision.capture` の非同期 capability result ではない。
desktop client、capability request、ongoing_action、capture timeout とは結び付けない。
LLM prompt でのユーザー発話と内部視覚文脈の分離方針は [../llm/プロンプト文脈分離方針.md](../llm/プロンプト文脈分離方針.md) を正とする。

## 境界

この機能で行うこと:

- `POST /api/conversation` が任意の `images` を受け取る
- 画像を詳細な視覚説明へ変換する
- 観測要約を `recall_hint / RecallPack / decision / speech` の入力へ反映する
- raw image payload を保存せず、詳細な視覚説明を `visual_observation_record` として残す

禁止すること:

- `text` を任意化する
- OCR 全文抽出
- UI 要素や座標の構造化
- raw 画像の長期保存
- 音声や動画入力
- 添付画像だけから `world_state.visual_context` を更新すること

## API 形状

`POST /api/conversation` の request body は次を受ける。

```json
{
  "text": "この画面どう見える？",
  "images": ["data:image/png;base64,..."],
  "client_context": {
    "source": "CocoroConsole",
    "client_id": "console-...",
    "active_app": "Browser",
    "window_title": "docs | Browser",
    "locale": "ja-JP"
  }
}
```

- `text` は必須の string
- `images` は任意の Data URI 配列
- 1 回の通常会話で扱う画像は 1 件に固定する
- `client_context` は任意の object

## パイプラインと保存

会話添付画像は共通入力の `input_materials` に配置する。
処理順、観測の確定、媒体の解放、失敗単位は [周辺環境](../runtime/周辺環境.md) を正とする。
LLMの観測説明は [入力解釈](../llm/入力解釈.md)、保存する視覚記録と検索は [視覚記録](vision_capture画像意味理解.md) を参照する。
人物発話は `current_input.text` の原文を保ち、画像から現在の部屋や人物活動を直接更新しない。

## failure の扱い

- `images` が配列でない、空文字要素を含む、Data URI でない、または 2 件以上の場合は `400 invalid_images`
- 画像観測要約が失敗した場合は cycle を `internal_failure` として残す
- silent fallback で画像なし会話へ丸めない

## 他設計との関係

- 画像の生成契約は [入力解釈](../llm/入力解釈.md) を参照する
- `world_state` への反映先は [../runtime/world_state.md](../runtime/world_state.md) を正とし、通常会話の添付画像は短期世界状態の正本にしない
- API 通信仕様の正本は [../api/bootstrapと入力.md](../api/bootstrapと入力.md) とする
