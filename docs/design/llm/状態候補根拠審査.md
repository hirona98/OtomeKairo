# 状態候補根拠審査

`world_state_grounding_review` と `activity_state_grounding_review` は、非空の状態候補を保存前に一次根拠と照合する LLM 補助処理である。意味境界は [world_state](../runtime/world_state.md) と [activity_state](../runtime/activity_state.md) を正とする。

入力は独立した `persona_context`、元の `source_pack`、生成済みの `candidate`。人格と候補文は一次観測と分ける。候補の要約、対象、人物、時期の全てが、その状態種別または人物活動の意味境界で支えられるかを審査する。移動や作業の報告でも、現在地が明示されていれば location 候補の根拠になる。普段の好みの訂正は、現在実行中の活動の対象を変える根拠にしない。

出力は `decisions` だけを持つ JSON object とし、全候補に1件ずつ次を返す。

```json
{"decisions": [{"reason_summary": "候補の全内容と一次根拠の照合結果", "evidence_kind": "supported_report", "index": 0}]}
```

`evidence_kind` は `supported_report / supported_observation / question / assistant_activity / persona_setting / inference / none`。最初の2種は候補の全内容が明示報告または直接観測で支えられることを表す。一部でも補った事実や状態種別のずれがあれば inference とする。人物報告の音も明示報告であり、視覚情報を音や温度の直接観測にしない。

コードは件数、位置、重複、enum を検証し、最初の2種の候補だけを元の順序で採用する。要約の補完や代替候補は行わない。契約失敗は審査を1回 repair し、なお失敗した場合は状態更新を失敗させる。カメラ観測から入力人物の活動を採用する同定条件は activity_state を正とする。
