# 状態候補の根拠判定

この文書は、状態候補を保存前に一次根拠と照合する LLM 判定の共通規則を定める。意味境界は [world_state](../runtime/world_state.md) と [activity_state](../runtime/activity_state.md) を正とする。

`world_state` では、候補生成と同じ応答に根拠判定を含める。出力の shape と呼び出し境界は [world_state の LLM 更新契約](../runtime/world_state.md#llm-更新契約) を正とする。

`activity_state` では、生成済みの非空候補を独立した `activity_state_grounding_review` に渡す。入力は独立した `persona_context`、元の `source_pack`、生成済みの `candidate` とする。

どちらも人格と候補文を一次観測と分け、候補の要約、対象、人物、時期の全てが、その状態種別または人物活動の意味境界で支えられるかを判定する。移動や作業の報告でも、現在地が明示されていれば location 候補の根拠になる。普段の好みの訂正は、現在実行中の活動の対象を変える根拠にしない。

`activity_state_grounding_review` の出力は `decisions` だけを持つ JSON object とし、全候補に1件ずつ次を返す。

```json
{"decisions": [{"reason_summary": "候補の全内容と一次根拠の照合結果", "evidence_kind": "supported_report", "index": 0}]}
```

`evidence_kind` は `supported_report / supported_observation / question / assistant_activity / persona_setting / inference / none`。最初の2種は候補の全内容が明示報告または直接観測で支えられることを表す。一部でも補った事実や状態種別のずれがあれば inference とする。人物報告の音も明示報告であり、視覚情報を音や温度の直接観測にしない。

コードは各生成の出力契約を検証し、最初の2種の候補だけを元の順序で採用する。`world_state` は候補ごとの参照、根拠種別、非空の理由を検証し、`activity_state_grounding_review` は候補件数、位置、重複、enum、非空の理由を検証する。判定が不正な候補も、採用候補の選別より先に契約検証を通す。要約の補完や代替候補は行わない。

契約違反時の repair と失敗範囲は [LLM補助契約共通](LLM補助契約共通.md) と各状態の設計を参照する。カメラ観測から入力人物の活動を採用する同定条件は activity_state を正とする。
