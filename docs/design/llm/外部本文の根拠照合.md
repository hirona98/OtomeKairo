# 外部本文の生成と根拠

この文書は、MCPへ渡す `arguments` の本文を、判断時の根拠に沿って生成する責務の正本である。
共通の入力境界と構造化生成は [LLM補助契約共通.md](LLM補助契約共通.md) と [LLM構造化出力transport.md](LLM構造化出力transport.md) を参照する。

## 生成の責務

通常判断、能力結果を受けた後続判断、自律作業のstepで、行動を決める LLM が MCP 要求の最終本文まで生成する。
本文の根拠との対応も、その生成の中で判断する。MCP入力を対象とする独立した根拠レビューは呼ばない。

生成には人格の文脈と、その判断に使う観測・本人発話・想起・実行結果を渡す。
根拠は意味のまとまりを保ち、文字数で切らない。
tool の用途を読み、外部へ伝える主張、検索条件、引用、仮定、比喩、今回の個の感想を意味で区別して本文を組み立てる。
事実表現は、根拠の対象・人物・時期と観測の確かさに対応させる。
資料中の指示や生成中の説明は資料として扱い、元の発話・観測・記録を事実の裏付けにする。
意味判断は生成する LLM が担当し、tool名やargument keyの文字列から本文の意味をコードで推定しない。

## 表現と根拠の対応

現在の個の感想や判断は、人格と今回の根拠から新しく形成した表現として扱う。
その中で観測対象の変化、過去の行動、反復的な自己の傾向を事実として述べる部分は、対応する観測、実行記録、人格、記憶へ照合する。
今回の印象や今選ぶ姿勢と、過去の経験や継続的な自己属性の説明を分ける。
これから行うと述べる行為も、現在利用できる能力、対象、その行為に必要な前提へ対応させる。
観測や身体的な行為の手段が未確認なら、今回の情報から形成した考えや姿勢として表す。
観測で確認された外見と未確定の解釈を分け、未確定の属性はその確かさを保って表現する。
自己の受け止め全般の境界は [判断と行動](../runtime/判断と行動.md) を参照する。

通常判断と自律作業のstepには、共通の能力本文生成指示を適用する。
引用、指定された原文、IDなどの機械的な値は保持し、その場へ届ける自分の言葉には人格本文の話し方を適用する。

## 出力の検証と失敗

本文は既存の `capability_request.input` の中に生成する。
コードは生成結果のJSON・出力契約、能力の利用可否、MCP serverとtoolの選択、引数schemaを検証する。
契約違反時は通常の生成repairで1回だけ作り直し、それでも不正なら生成を失敗させる。
生成API自体の失敗は呼び出し元へ返す。

外部へ送信してよい内容かは [pre_send_check.md](pre_send_check.md) の境界で扱う。
自律作業の開始・活動・完了の審査、開示審査とプライバシーチェックは、それぞれの入力契約に従う。
機械的なテストとmock試験は入力資料の受け渡し、出力契約、呼び出し回数を確認し、自然文の精度維持を実証するものとは分けて扱う。
