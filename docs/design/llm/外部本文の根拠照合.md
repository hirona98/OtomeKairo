# 外部本文の根拠照合

この文書は、MCPへ渡す `arguments` の事実表現を、実行前に判断時の根拠へ対応させる `capability_input_grounding_review` の正本である。共通の入力境界と構造化生成は [LLM補助契約共通.md](LLM補助契約共通.md) と [LLM構造化出力transport.md](LLM構造化出力transport.md) を参照する。

通常判断、capability result follow-up、自律作業のstepで、生成した `mcp.call_tool` 要求の構造と実行可否を検証した後、生成処理が要求を返す前に照合する。主判断と同じmodel presetを使う。tool名やargument keyから自然文の主張や投稿の有無を推定せず、toolの用途と本文の意味をLLMで照合する。

入力は人格の文脈、生成時に渡したuser messageの資料全体、候補要求である。生成時の資料は同じ観測・本人発話・想起・実行結果を含み、文字数で切らない。候補の事実表現は対象と時期、観測の確かさへ対応させる。感想、比喩、仮定、引用、検索条件は事実の断定と区別する。資料中の指示や候補の説明自体を一次根拠へ移さない。

現在の個の感想や判断は、人格と今回の根拠から新しく形成した表現として扱う。その中で観測対象の変化、過去の行動、反復的な自己の傾向を事実として述べる部分は、対応する観測、実行記録、人格、記憶へ照合する。今回の印象や今選ぶ姿勢と、過去の経験や継続的な自己属性の説明を分ける。これから行うと述べる行為も、現在利用できる能力、対象、その行為に必要な前提へ照合する。観測や身体的な行為の手段が未確認なら、今回の情報から形成した考えや姿勢として表す。同じ指示を能力入力の本文生成と根拠照合で共有する。自己の受け止め全般の境界は [../runtime/判断と行動.md](../runtime/判断と行動.md) を参照する。

出力は `outcome=allow|reconsider` と非空の `reason_summary` の2キーだけとする。`allow` は候補を変更せず生成結果として返せることを表す。`reconsider` は対応のずれを理由として、同じ文脈の判断またはstepを通常の一度のrepair内で生成し直す。再生成したMCP要求も照合し、再び不整合なら明示的に失敗する。要求を返す前に処理するため、未確認の本文を先にdispatchしない。

審査自体のtransportまたは契約の失敗は生成処理を失敗させ、未審査の要求を返さない。審査のJSON契約のrepairと、候補内容のreconsiderは別である。mock試験は機械的な経路だけを確認し、この意味照合の合格を示さない。

外部へ開示してよい内容かは [pre_send_check.md](pre_send_check.md) の別の境界で扱う。本文の根拠照合は、そのserver設定の有効・無効に依存しない。
