# 入力解釈

選択中のモデルで、現在入力と原観測から想起方針、回答根拠の契約、観測説明と意味上の変化を一回で生成する。
観測型・処理順・保存は [周辺環境](../runtime/周辺環境.md) を正とする。
独立した `visual_observation` role は設けない。

## LLM 入力

入力解釈と行動判断は、同じ snapshot から role の範囲に応じた view を作る。
`current_input` と `persona_context` は既存の独立した文脈を維持する。
選択中の同じ生成モデルプリセットを使い、画像専用のモデル割り当ては追加しない。

| 欄 | 内容 |
| --- | --- |
| `surroundings` | snapshot 参照、現在観測、取得状況、根拠付き短期状態 |
| `input_materials` | 会話添付・wake reference の資料と、それぞれの出所 |
| `observation_comparisons` | 同じ source / channel の前回観測と直近発話に使用した観測 |

`surroundings` の field は `snapshot_ref / snapshot_time_text / observations / source_reports / state_summaries` とする。
`input_materials` は `observations / reference_texts` を持ち、本文と出所を資料単位で保つ。
`observations` の項目は観測の正本IDである `ref`、設定側のsourceを表すrequest-localな `source_ref`、source の種類・表示名・所有境界、場所、
`time_basis / time_text / age_text`、`kind / payload / interpretation` を持つ。
初回の `interpretation` は `null`、行動判断では対応する検証済みの説明・確信度・変化判定を入れる。
payload の数値と単位は原観測と同じ値を使う。event は `monitoring_started_time_text / last_occurred_time_text` に生活時刻を示し、最後の反応が未記録なら後者を `null` にする。受信 API の timestamp キーとは区別する。
state summary は `state_ref / source_observation_refs / summary_text / source_kind / source_ref / time_text` を持つ。`state_ref`は状態の正本IDである。保存された状態を前景要約へ投影する際も`world_state_id`を保持し、判断入力まで同じIDを受け渡す。`source_observation_refs`と保存時の`source_observation_ids`には共通の観測IDを使い、未設定なら空配列とする。
原観測の詳細説明と派生状態の短い要約は、それぞれの出所と時点に沿って照合する。

`source_reports` の各項目は、source / channel、場所、`status / status_time_text / error_code` を持つ。
失敗した source の以前の値を、この項目の現在値として添えない。
`observation_comparisons` は当回の観測参照ごとに前回と直近発話の説明・原測定値・時刻を結び付ける。
有効な観測と一対一の項目を持ち、`observation_ref / source_identity_changed / previous_observation_context / last_prompted_observation_context` を明示する。
比較資料がない項目は省略せず、対応する context を `null` とする。観測元の識別条件に変更がなければ `source_identity_changed` は `false` とする。
同一 sample を判別できる場合は `same_sample` も添える。
これらの比較資料は現在の観測一覧へ再掲しない。

`surroundings` と `input_materials` の JSON に raw image や base64 を入れない。
JSON の `media_ref` に対応する説明用 text part と image part を同じ message に並べる。
媒体参照と画像の件数不一致、参照欠落、他 snapshot の画像参照は送信前に失敗させる。
時刻は生活時刻の自然文と相対時間で示す。
送信時にも snapshot の基準時刻と観測時刻を保つ。

行動判断では、各観測に入力解釈の説明を対応付ける。
測定値は取得した値、説明文はその値や画像からの解釈であることを示す。
元画像と派生説明を、別々の独立した根拠にはしない。
派生した環境・視覚の短期状態も `surroundings` へ集め、同じ説明を他の prompt 欄に再掲しない。
既存の環境以外の `foreground_world_state` はその役割を維持する。
prompt 向け `current_visual_observations` はこの共通入力へ置き換え、二つの入力契約を併存させない。

## 統合入力解釈の出力契約

measurementに添えられたproducerの数値分類は、[測定上の変化情報](../runtime/周辺環境.md#測定上の変化情報)として読み、以下の意味上の`change_state`とは区別して判断する。

トップレベルは `recall_hint / answer_contract / observation_interpretations` の三つとする。
前二つの内容は既存の入力解釈契約を維持する。
`observation_interpretations` はこの view の有効な観測と一対一に対応する配列である。
観測のない通常入力や、観測を隔離した入力では空配列とする。

各項目は次の形に固定する。

```json
{
  "observation_ref": "visual_observation:12",
  "summary_text": "机と椅子が見え、机の上に白い容器が置かれている。容器の中身は画像から判別できない。",
  "confidence_hint": "medium",
  "change_state": "stable",
  "change_basis": "semantic_stability",
  "change_reason_summary": "前回と主要な物体の配置は同じである。"
}
```

`observation_ref` は入力で提示された観測の正本IDをそのまま選ぶ。識別子の発行と参照の境界は [LLM補助契約共通](LLM補助契約共通.md) を正とする。
観測 ID、source、場所、人物同定根拠、観測時刻、値、単位、有効期限を LLM に生成させない。
server が原観測と生成結果を参照で結び付ける。
summary はその観測だけで確かめられる内容と不確実な点を記述する。
温湿度、人感、画像を総合した見方は、想起方針や後続の行動判断で扱う。
「画像で人物が見えない」と「人感が反応した」は、それぞれの根拠のまま残す。
confidence は説明・解釈の確からしさであり、測定器の精度を表さない。

`summary_text` は観測一件につき 1200 文字以内、`change_reason_summary` は 240 文字以内とする。
本文をコードで切らず、超過を契約違反として扱う。
主要な対象、形・色・配置、状態、不確実な点が伝わる説明を生成する。
資格情報などの保存境界は現行の視覚記録の規則を維持する。

`confidence_hint` は `low / medium / high` とする。

| change_state | change_basis | 意味 |
| --- | --- | --- |
| first_seen | no_previous_observation | 同じ観測元の比較対象がない |
| changed | semantic_change | 前回から意味上の変化がある |
| changed | source_identity_changed | 観測元の識別条件が変わった |
| stable | semantic_stability | 前回と意味上同じ |
| same_as_recent_speech | recent_speech_repetition | 直近で発話した内容と同じ |

比較は同じ source / channel / 場所 / 所有境界の観測だけを対象にする。
source の比較 identity が変わった場合は以前の比較資料を渡さず、その変更を機械的な比較 metadata として渡す。
この場合の `source_identity_changed` と、過去資料自体がない `no_previous_observation` を区別する。
観測比較の根拠は、同じ `observation_ref` の `observation_comparisons` にある資料に限定する。
`recent_turns` は会話理解と想起に使う別の文脈である。
`source_identity_changed=true` を優先し、それ以外で `previous_observation_context=null` なら `first_seen / no_previous_observation` とする。
再起動後に会話履歴が残っていても、同じ観測元の比較資料がなければこの初回判定に従う。
`same_as_recent_speech` は、前回観測と直近発話に使用した観測の比較資料がともにある場合に判断する。
測定値の大小や発話の語句で変化の意味をコード側から決めない。
過去の説明は比較に使い、現在の画像の同定結果へ転写しない。
同一 sample の再利用はコードが識別し、新たに測定・検知した事実にはしない。
直近発話に使った観測は、実際に発話した event と構造化された採用根拠から更新する。
発話を保存する前の候補選択や、発話本文のキーワードからは更新しない。配送成否は既存の音声・event配送の記録と分ける。

validator は観測参照の完全一致、重複・欠落、許可キー、型、enum、文字数、比較資料の有無との整合を検証する。
自然文から `speech / noop`、人物の状態、視覚変化を機械的に分類しない。
provider schema と repair の契約は [既存 transport](LLM構造化出力transport.md) に従う。
repair は同じ画像・値・参照・schema を使い、新たに観測を取得しない。
初回と repair は同じ観測比較の指示を使う。比較資料との整合に失敗した場合は、対象の `observation_ref` と資料の有無・期待する状態と根拠の組を validator error に含める。
provider schema は共通の配列型を使う。件数上限は snapshot、出力の件数と参照の完全対応は validator で検証する。
