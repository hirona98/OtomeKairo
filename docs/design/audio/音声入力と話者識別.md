# 音声入力と話者識別

## 正本境界

この文書は、音声入力、入力リース、発話区間、STT、音声起動ワード、話者識別、話者登録、音声由来の対話入力の意味規則を正本にする。
HTTP / WebSocket の path、message、error code は [../api/audio_stream.md](../api/audio_stream.md) を正とする。
アバター音声設定の wire shape は [../api/状態と設定.md](../api/状態と設定.md)、人物と相互作用の一般規則は [../foundation/人物と相互作用.md](../foundation/人物と相互作用.md) を正とする。

## 責務境界

OtomeKairo server は次を実行する。

- 入力リースの管理
- 音声フレームの検証
- VAD と発話区間の構築
- STT
- 音声起動ワード判定
- 話者 embedding の生成、登録、識別
- `person_ref` と `interaction_ref` の確定
- 対話入力の生成
- 応答先 client の確定

ブラウザ、CocoroConsole、microphone connector は音声を取得し、指定形式へ変換して送る。
ブラウザ、CocoroConsole、microphone connector は VAD、STT、音声起動ワード判定、話者識別を実行しない。
microphone connector は capability connector ではなく、OtomeKairo の音声入力 source を提供する入力 connector である。

CocoroConsole は通常入力元が `console_microphone` の間だけ、設定された Windows input endpoint から音声を取得する。
CocoroConsole は音声設定と話者登録を OtomeKairo の API で操作し、`conversation_input` と `assistant_message` を表示し、`assistant_audio` のWAVを再生先へ配送する。
`microphone_settings.console` が未設定の場合、音声設定を保存する CocoroConsole は自身の安定した client ID を `microphone_settings.console.client_id` へ設定する。
Windows input endpoint が未選択の場合は `microphone_settings.console.input_device` を `null` にする。
別の CocoroConsole の設定が存在し、現在の端末で Windows input endpoint を選択していない場合は既存設定を保持する。
OtomeKairo は発話本文の生成後にTTSを実行し、入力元clientへWAVを配送する。
TTSのwire契約と失敗境界は [../api/event_stream.md](../api/event_stream.md) を正とする。

## 入力 source

音声入力 source は次の 3 種類に固定する。

- `local_microphone`
  - Ubuntu 上の `connectors/microphone/` process が提供する
  - 音声起動ワード判定を適用する
  - 通常入力時の応答先は `microphone_settings.console.client_id` とする
- `console_microphone`
  - `microphone_settings.console.client_id` と一致する CocoroConsole が提供する
  - 音声起動ワード判定を適用する
  - 通常入力時の応答先は同じ CocoroConsole とする
- `web_microphone`
  - 同一 origin のブラウザ UI が提供する
  - Web 入力 session の明示的な開始操作から停止までを ACTIVE として扱う
  - 音声起動ワード判定を適用しない
  - 応答先は Web 入力 session の owner とする

同時に有効な入力 source は 1 件に固定する。
`microphone_settings.input_source` は3種類の入力元から1件を選び、DBへ保存する。
Web 入力 session が存在しない間は、`local_microphone` と `console_microphone` を通常入力として扱う。
`web_microphone` はWeb入力sessionが存在する間だけ音声を取得し、sessionが存在しない間は入力を停止する。
Web 入力 session は開始時の `microphone_settings.input_source` を使用し、独自の入力元選択を持たない。
Web 入力 session の `local_microphone` と `console_microphone` は各外部processの音声を session owner へ配送する。
Web 入力 session の開始は現在の入力リースを即時に失効させる。
Web 入力 session の停止、owner の event stream 切断、Web audio stream 切断、音声設定変更ではsessionを終了する。
session終了後は保存済み入力元の通常動作へ戻る。
選択した入力元または応答先を利用できない場合は入力を停止し、別の入力元または応答先へ切り替えない。

入力リースは単調増加する generation を持つ。
generation が失効した接続から届いた音声は処理しない。
source、入力 session、応答先の切替時は VAD state、構築中の発話、処理待ち発話を破棄する。

## 音声形式

server が受理する形式を次に固定する。

- sample rate: 16000 Hz
- channel: mono
- sample: signed PCM 16-bit little-endian
- frame duration: 20 ms
- samples per frame: 320
- bytes per frame: 640
- container: なし

1 WebSocket binary message は 1 frame と一致させる。
WAV header、圧縮音声、複数 frame の結合、奇数 byte、fragmented WebSocket message は受理しない。
server は 320 sample frame を連結し、Silero VAD の 512 sample window へ組み替える。

## microphone connector

microphone connector は Ubuntu を初期対応環境にする。
connector は `sounddevice.RawInputStream` と PortAudio の ALSA host API を使用する。
connector は選択 device の既定 sample rate、float32 mono で取得する。
入力が 16000 Hz ではない場合は `soxr.ResampleStream` で 16000 Hz へ変換する。
16000 Hz の入力には resampling を適用しない。
PCM16LE へ変換した後、20 ms frame として送る。

connector 固有依存は `connectors/microphone/` の venv に閉じる。
OtomeKairo server の root package へ PortAudio、sounddevice、soxr を追加しない。
connector のローカル設定は server URL、`client_id`、token 明示値に限定する。

device 選択の正本は `config.db` の `microphone_settings.local_input_device` に置く。
device identity は PortAudio host API 名と完全な device 名の組で表す。
PortAudio の一時的な数値 index を保存しない。
同じ host API 名と device 名が複数存在する状態は曖昧として扱い、入力を開始しない。
選択 device が存在しない場合は OS default device へ切り替えない。

device 切断時はリースを解放し、同じ device identity を 5 秒間隔で探索する。
同じ device が復帰した場合は新しい `audio_start` から再開する。
microphone connector の process が終了した場合は、単一 systemd service 全体を終了し、systemd の restart に任せる。
音声入力設定が無効な間も connector process は終了せず待機する。

## Web 音声取得

Web UI は `getUserMedia` と `AudioWorklet` を使用する。
`MediaRecorder` は使用しない。
Web UI は mono へ downmix し、16000 Hz へ resample し、PCM16LE 20 ms frame を生成する。

希望 media constraints を次に固定する。

- `echoCancellation=true`
- `noiseSuppression=true`
- `autoGainControl=false`

ブラウザが希望値を提供できない場合も録音を失敗にしない。
実際の `MediaTrackSettings` を `audio_start` へ含め、inspection 用 metadata として扱う。
browser が echo cancellation、noise suppression、auto gain control の実値を公開しない場合は `null` とする。

Web UI の device 選択は origin 単位の `localStorage` に `deviceId` を保存する。
保存 device が存在しない場合は default device へ切り替えず、利用者へ再選択を求める。
tab の非表示、navigation、reload、切断では録音を停止する。
tab が再び表示されても自動再開しない。

## CocoroConsole 音声取得

CocoroConsole は NAudio の WASAPI capture を使用する。
通常入力元が `console_microphone` の場合は `microphone_settings.console.input_device` を必須とする。
選択 device は `microphone_settings.console.input_device.device_id` と完全一致する endpoint とする。
一時的な device index と Windows default device を使用しない。
選択 endpoint が存在しない場合は入力を開始しない。

CocoroConsole は capture format を signed PCM 16-bit、16000 Hz、mono に固定する。
capture callback の境界を wire frame の境界として扱わず、640 byte ごとに組み替えて送る。
送信は単一の bounded queue と単一 sender で直列化する。
pause、lease 失効、source 切替時は未送信 frame を破棄する。
音声をファイルへ保存しない。

## VAD と発話区間

Silero VAD ONNX を server 起動時に CPU provider で読み込む。
VAD state は入力リースごとに独立し、source 切替時に reset する。

VAD の固定条件を次に定める。

- model input window: 512 samples at 16000 Hz
- probability threshold: `microphone_settings.vad_probability_threshold`
- threshold default: `0.5`
- threshold range: `0.1..0.9`
- pre-buffer: 500 ms
- speech end silence: 500 ms
- minimum voiced duration: 500 ms
- maximum utterance duration: 15 seconds

minimum voiced duration は最初の VAD-positive sample から最後の VAD-positive sample までで測る。
pre-buffer と trailing silence を voiced duration に含めない。
500 ms 未満の発話は STT と話者識別へ渡さない。
15 秒に達した発話は強制終了し、継続音声を次の発話として構築する。

同じ発話から次の 2 つの in-memory PCM view を作る。

- AmiVoice view
  - 500 ms pre-buffer から 500 ms trailing silence までを含む
- WeSpeaker view
  - 最初の VAD-positive sample から最後の VAD-positive sample までを含む
  - 発話内部の短い無音は保持する

raw frame、発話 PCM、WAV、話者登録音声をファイルまたは DB へ保存しない。

## 発話キュー

音声発話は入力生成順の FIFO で処理する。
同時処理は 1 発話、待機は 4 発話までとする。
各発話にリース generation 内で単調増加する `utterance_seq` を付ける。

キュー先頭の同じ PCM から AmiVoice STT と WeSpeaker 話者識別を並列実行する。
両方が完了するまで次の発話を処理しない。
両方が成功し、音声起動条件を満たした場合だけ対話入力を作る。
発話処理が完了した後に PCM view を解放する。

待機数が 4 件に達した場合は入力 source へ `pause` を送り、新しい frame の送信を止める。
待機枠が空いた場合は `resume` を送る。
disk への spill は実行しない。

## AmiVoice STT

AmiVoice の同期 HTTP API を使用する。
endpoint は `/v1/nolog/recognize` に固定し、`/v1/recognize` と別 endpoint へ切り替えない。
音声は multipart の最終 `a` part に raw PCM を指定し、`c=LSB16K` を指定する。
grammar は `-a-general` に固定する。

`profile_id` は空文字または `[A-Za-z0-9_-]+` に一致させる。
`__` で始まる値は受理しない。
空文字では profile parameter を送らない。
送信時は `profileId=:{profile_id}` とし、AmiVoiceのプロフィール参照に必要なcolonを音声認識clientが付加する。

API 呼び出しの total timeout は 30 秒に固定する。
再試行は実行しない。
成功条件を次に固定する。

- HTTP request が成功する
- response の `code` が空文字
- response の `message` が空文字
- top-level `text` が空ではない

provider confidence は inspection metadata にだけ使用する。
confidence による採否判定を実行しない。
受理した文字起こしだけを通常の対話入力として保存する。

音声起動ワード待機中も各 VAD 発話を AmiVoice へ送る。
音声起動ワード不一致、話者不明、短すぎる発話、STT失敗の文字起こしは、会話、memory、trace、inspection、event、debug log に残さない。

## 音声起動ワード

音声起動ワード設定は選択中人格設定の `persona.wake_words` の文字列配列とする。
各値は前後空白を除いた非空文字列とし、重複を受理しない。
アバター音声プリセット（`avatar.stt`）には持たない。
`avatar.stt.wake_words` を含む保存は未対応フィールドとして拒否する。
旧 `wake_word` 文字列と comma 区切り解釈は実装しない。

文字起こしと各音声起動ワードへ Unicode NFKC normalize と casefold を適用し、文字起こしの prefix として一致した場合だけ起動する。
途中一致、同義語、filler、語彙リスト、LLM 意味判定は使用しない。
正規化値は一致判定だけに使用する。
対話入力には音声起動ワードを含む AmiVoice の元文字列全体を渡す。
採用された対話入力の trace metadata に `matched_wake_word` を構造化して残す。

Web 入力 session が存在しない通常入力では、`local_microphone` と `console_microphone` に次の状態を使用する。

- `waiting`
  - 音声起動ワード一致を待つ
- `active`
  - 登録話者の対話入力を作る

音声起動ワードが空配列の場合は常時 `active` とする。
一致後は 60 秒間 `active` とする。
登録話者の対話入力を正常に作るたびに 60 秒を更新する。
短い発話、STT失敗、話者不明、音声起動ワード不一致では期限を更新しない。

Web 入力 session は3種類の入力元のどれを使用しても開始から停止まで `active` とし、この状態機械を使用しない。

## 話者 embedding

WeSpeaker ResNet34 ONNX を server 起動時に CPU provider で読み込む。
Fbank は `kaldi-native-fbank` を使用し、次の設定に固定する。

- sample rate: 16000 Hz
- mel bins: 80
- frame length: 25 ms
- frame shift: 10 ms
- window: Hamming
- dither: 0
- utterance CMN: enabled

model output は 256 次元として検証し、L2 normalize する。
話者照合は L2 normalize 済み embedding の cosine similarity で行う。
ONNX session の intra-op threads と inter-op threads は 1、execution mode は sequential に固定する。
GPU、CUDA、別 provider は使用しない。

登録済み embedding が 0 件の場合、通常音声入力を開始せず `speaker_enrollment_required` とする。
発話ごとに全 active embedding と照合する。
top1 similarity は `microphone_settings.speaker_recognition_threshold` 以上を必須とする。
threshold の既定値は `0.6`、範囲は `0.1..0.9` とする。
active embedding が 2 件以上の場合は `top1 - top2 >= 0.05` も必須とする。
条件を満たさない発話は `speaker_unidentified` とする。

初期実装は 1 発話に 1 人が含まれる前提とする。
重なり話者の分離、diarization、発話内の話者切替は実装しない。
閾値を通過した場合は発話全体を top1 の人物へ帰属する。

## 話者登録

Web UI は話者一覧を「登録済み話者」、未割当の呼ばれ方を選ぶ操作を「新規登録」と表示する。

話者登録は server 全体で同時に 1 session とする。
開始 client が session owner になる。
別 client の開始は `speaker_enrollment_busy` とする。
owner だけが中止できる。
owner の event stream 切断または開始から 2 分経過で session を中止し、途中結果を破棄する。

登録中は入力 mode を `enrollment` へ切り替える。
登録発話は AmiVoice、音声起動ワード、対話、memory へ渡さない。
現在リースを持つ `local_microphone`、`console_microphone`、`web_microphone` のいずれかから取得する。
STT が無効または AmiVoice API key が空でも話者登録を実行する。

任意内容の発話を 3 件取得する。
各発話は VAD-positive 範囲が 2 秒以上であることを必須とする。
各発話の normalize 済み embedding を生成し、3 件の平均を L2 normalize する。
完成した 1 embedding だけを 1 transaction で保存する。
raw音声と各発話 embedding は保存後に破棄する。

新規登録では UUID を生成し、`person:voice:<UUID>` を割り当てる。
再登録では既存 `person_ref` を維持し、完成した embedding と model metadata を原子的に交換する。
再登録が失敗した場合は既存 embedding を維持する。

表示名は embedding と独立して変更する。
表示名変更は過去の event、memory、会話履歴を更新しない。
音声登録解除では embedding を削除し、人物 row、`person_ref`、表示名、memory、会話履歴を残す。
再登録時は同じ `person_ref` を再利用する。

## 音声人物と相互作用

音声識別で確定した人物は `person:voice:<UUID>` を使用する。
音声による直接相互作用は `interaction:voice:direct:<UUID>` を使用する。
異なる入力 source で同じ話者を識別した場合は、同じ `person_ref` と `interaction_ref` を使用する。
Web テキストの `person:web:*` と音声人物は自動統合しない。

各発話を独立して話者識別する。
ACTIVE 状態は部屋と入力 source の起動状態であり、直前人物の認証状態ではない。
別の登録話者が次の発話を行った場合は、その人物の相互作用として扱う。

## 対話入力と応答配送

STT、話者識別、音声起動条件が成功した場合、通常の会話判断サイクルを開始する前に `conversation_input` を入力元表示 client へ送る。
`conversation_input` は文字起こし、`interaction_ref`、`speaker_ref`、表示名、音声 source を含む。
音声起動ワード不一致、話者不明、短い発話、STT失敗では送らない。
後続の判断サイクルが失敗しても、表示済みの `conversation_input` は取り消さない。

対話入力の `speaker_ref` と participant は識別した `person_ref` とする。
選択中 `memory_set_id` と `interaction_ref` を使い、既存の会話判断パイプラインへ入力する。

`local_microphone` と `console_microphone` の通常入力による `conversation_input`、`assistant_message`、`assistant_audio` は `microphone_settings.console.client_id` の client だけへ配送する。
対象 client が接続しておらず、必要な event を購読していない場合は入力を停止する。
接続 client が 1 件だけという理由で配送先を補完しない。

Web 入力 session 中の `conversation_input`、`assistant_message`、`assistant_audio` は、選択 source にかかわらず session owner だけへ配送する。
Web session 切断後に別 client へ配送しない。
microphone connector は表示と TTS の配送先にしない。

## 設定変更

次の変更では音声入力を pause し、VAD state、構築中発話、待機キューを破棄し、設定 generation を更新する。
実行中の旧 generation の結果は採用しない。

- 選択アバター変更
- 選択アバターの STT 有効状態変更
- AmiVoice API key または profile ID 変更
- 選択人格設定変更
- 選択人格設定の音声起動ワード変更
- VAD threshold 変更
- speaker recognition threshold 変更
- 保存入力 source、local device、CocoroConsole clientまたはdevice変更

値が変わらない保存と話者表示名だけの変更では generation を更新しない。
設定保存は revision conflict を設けず、後から成功した保存内容を正本にする。

`avatar.stt.enabled=false` では通常音声入力を停止する。
話者登録は STT 有効状態から独立して実行する。

## エラー分類

設定または形式に起因する次の失敗は audio configuration error とする。
入力を pause し、構築中発話と待機キューを破棄する。
設定保存によって原因が解消するまで自動再開しない。

- AmiVoice API key 不正
- grammar または profile 設定不正
- server が生成した音声形式を provider が拒否
- 選択 device または response client の設定不成立

次の失敗は発話単位の transient error とする。
当該発話を失敗にし、再試行せず、FIFO の次発話へ進む。
通常入力の ACTIVE 期限を更新しない。

- 文字起こしが空
- provider busy
- network timeout
- provider temporary internal error
- 話者識別不成立

Silero、WeSpeaker、ONNX Runtime、model file の欠損、hash 不一致、初期化失敗では、OtomeKairo server の HTTP、テキスト対話、自律処理、設定処理を起動したまま `audio_runtime_unavailable` とする。
model runtime は原因修正後の server restart でだけ再初期化する。
runtime file watcher と background retry は実装しない。
別 model と別 STT engine への fallback は実装しない。

## model とライセンス

Silero VAD と WeSpeaker の exact ONNX file を repository 内へ配置する。
runtime download は実行しない。
model manifest に model ID、source、license、SHA-256、input/output shape を記録する。
起動時の hash 不一致を `audio_runtime_unavailable` とする。
model 更新は file と manifest を同じ変更で更新し、登録済み話者との model ID 混在を受理しない。
model ID が変わった場合は全話者の再登録を必要とする。

## runtime state とログ

音声 runtime state は process-local とし、DBへ保存しない。
inspection は現在状態と直近 1 発話結果だけを返す。
過去の発話処理は `server.log` の metadata で追跡する。

音声 runtime state は少なくとも次を含む。

- availability と unavailable reason
- model ID
- selected device と connector state
- active source、lease generation、heartbeat
- mode
- VAD speaking、VAD probability、dBFS
- 通常入力の waiting / active と active deadline
- processing utterance、waiting queue、pause reason
- enrollment owner、target、completed sample count、deadline
- last utterance result

話者識別不成立の直近結果は top1 と top2 の `person_ref` と similarity を候補として返す。
表示名、文字起こし、音声、embedding は返さない。

event stream の `audio_runtime_state` は状態遷移時に即時送る。
dBFS と VAD probability の連続更新は最大 5 Hz にする。
event は差分ではなく毎回完全 snapshot を送る。
同一 snapshot は再送しない。

各発話の debug log は `utterance_seq`、source、voiced duration、queue、各処理時間、AmiVoice result code、top1/top2 similarity、最終 result code、設定 generation を記録する。
文字起こし、音声、表示名、`person_ref`、API key、embedding を記録しない。
既存 `server.log` の 5 MiB と 3 backup の rotation を使用し、音声専用ログを作らない。

## 明示的に受け入れる制約

CocoroConsole または CocoroShell のWAV再生中も選択中のマイク入力を継続する。
TTS 再生通知、入力 pause、文字起こし抑止、barge-in 制御を実装しない。
TTS 音声を再認識する可能性を運用上の既知リスクとして扱う。
