# 気にかけていること

動作設定として持つ関心と、定期思考での前景化の意味境界の正本。
設定 wire は [../api/状態と設定.md](../api/状態と設定.md)、initiative の一般契約は [自律initiative_loop.md](自律initiative_loop.md) を正とする。

## 目的

人は、定期思考の間隔では頻繁すぎる活動を、動作設定として書く。
server は、前回の着手から最短間隔が過ぎた活動を、到来した定期思考の候補として載せる。作業を開始せず、目的文も書かない。
着手するか、今はやめるか、着手したあとの働きかけは、その時点の個が決める。
気持ちや、今しばらくどちらへ向きやすいかは `drive_state` が持つ。この設定はそれではない。

## 設定と状態

`standing_concerns` は現在設定である。`wake_policy` と同列の動作設定であり、MCP 定義でも Agent Skill source でも、`drive_state` でもない。

各関心は次だけを持つ。

| 項目 | 役割 |
| --- | --- |
| `concern_id` | 設定内で一意の名前 |
| `enabled` | 前景化の対象にするか |
| `min_interval_seconds` | 前回の着手から、次に定期思考の候補へ出すまでの最短間隔 |
| `concern_summary` | 活動の説明。実行指示でも `autonomous_run` の目的文でもない。見る、返す、自分から書くがありうるなら、その範囲として書く |

`mcp_server_id` と `skill_ids` は持たない。手段は判断時の catalog と skill 選択に任せる。

`concern_summary` は、候補に出す活動の範囲を書く。見る、返す、自分から書く、のような関わり方がありうるなら、それを範囲として書く。実行手順、義務、定時確認にはしない。

最後に実際に関わった時刻は process-local の実行状態である。設定正本には置かない。process 再起動後は未関与として扱う。

新規既定状態は、disabled の ELYTH 例を 1 件持つ。これは設定例であり、ELYTH を server が特別扱いする根拠にはしない。

## due

enabled な関心は、次をすべて満たすとき due である。

- まだ着手した記録が無い、または最後に着手してから `min_interval_seconds` 以上経過している
- 同じ `concern_id` を `standing_concern_ids` に持つ非終端の `autonomous_run` が無い

着手していないのに `min_interval_seconds` を消化しない。
非終端は `active / waiting_timer / waiting_result / paused` である。`standing_concern_ids` を持たない run は、この抑制に使わない。
`replace_existing` で目的を変更するときは、置換対象の `standing_concern_ids` を新しい run に引き継ぎ、今回選択した活動の ID と重複なく合わせる。`create_new` では今回選択した活動だけを紐づける。これにより、置換をまたいでも活動の候補化を抑制する。
due 判定は時刻、設定値、run に保存した `concern_id` だけで行い、tool 名や skill 名の文字列一致は使わない。

## 前景化

due な関心は `workspace_context` の候補になる。`kind=standing_concern`、`factor_ref` は `standing_concern:<concern_id>`。
`summary_text` は `concern_summary` そのものである。定時、実行、確認せよ、を足さない。

定期思考の initiative では、due な関心を自発系の材料にする。偽の `drive_state` は作らない。
`autonomous` family は、due な関心があるとき available にしてよい。特定 capability を preferred にはしない。
due な関心があるときは、`initiative_entry_check` が `skip` でも定期思考サイクルを打ち切らない。視覚が安定していることや入口 skip は判断材料のまま残し、関心を判断盤面へ載せる。

`current_input.text` は定期思考の自己評価の説明のままにする。関心名、定期、due、実行を書かない。
判断プロンプトは、`standing_concern` を実行指示ではなく、今回の候補に出ている活動として渡す。間隔が過ぎたことは server が候補へ出す前に判定し、プロンプトには書かない。
通常判断の Skill 選択も、`wake / background_thinking` で due な関心の `concern_summary` そのものを同じ意味で参照する。渡す境界と選択契約は [../integration/AgentSkills統合.md](../integration/AgentSkills統合.md) を正とする。
自身の活動の比較プロンプトは、今その活動に着手するかを問う。着手するなら、見る、返す、自分から書くのどれが自然かも同じ問いに含める。

関わらないことも許す。独り言と、気にかけていることへの関与は別比較である。比較の問いと合成は [判断と行動.md](判断と行動.md) を正とする。
関わると決めたとき、`autonomous_run.objective_summary` は個が今の言葉で書く。設定文をコピーしない。

カメラやスクショは感覚であり、ユーザー側の働きかけや環境である。この設定の活動は、自身の活動である。
マスターへの関与と、気にかけていることへの関与は別比較である。同じ判断理由に畳まない。
定期思考と API 起床では、due な関心があるとき自身の活動とマスターへの関与を別比較する。
自身の活動の比較には、人物側の視覚や活動を材料にしない。
材料の範囲は [判断と行動.md](判断と行動.md) の `comparison_scope=self_activity` を正とする。
どちらも毎回比べ、どちらも進めてよい。結果の合成は [判断と行動.md](判断と行動.md) を正とする。
着手を見送る理由は、今その活動に関わらないことに置く。人物の作業、集中、画面は使わない。
その関心に関われる手段が判断時の catalog に無い、または available でないときは、今は関わらない。
別の感覚や別の能力で代替しない。
視覚が取れないことは、活動の見送りの理由ではない。
これは判断 cycle に入ったあとの話である。対象 vision source がこの process で未登録のため cycle を開始しないことは [../api/状態と設定.md](../api/状態と設定.md) を正とする。
視覚の API 起床は定期思考の代替ではない。interval 起点は [自律initiative_loop.md](自律initiative_loop.md) を正とする。

届いた働きかけを見ることも、見る、返す、自分から書くと同じく、その活動の範囲である。専用の観測デーモンは持たない。見に行くと判断したとき、判断時の catalog にある手段を使う。

関心から始める今回の作業範囲と完了条件は [autonomous_run.md](autonomous_run.md#関心から始める作業の範囲) を正とする。

関心の間隔から作業の開始起点は足さない。複合行動は通常の `autonomous_run` であり、MCP 定義の属性ではない。実行境界は [autonomous_run.md](autonomous_run.md) を正とする。

## 実際に関わった

次をすべて満たした最終判断のとき、その関心に関わったとする。

- 自身の活動の比較が `autonomous_run` または `capability_request`
- その比較の `foreground_selection` の primary または supporting に、その関心の `factor_ref` がある

外向き比較の結果にかかわらず、自身の活動が進んでいれば更新する。
外向きだけの `speech`、両方の `noop`、`pending_intent` では更新しない。
送信前チェックで最終的に外向き実行へ至らなかった判断では更新しない。
人が同じ関心を見させた cycle でも、関心が workspace に載り、上の選択が付けば同じ規則で更新する。

## 定期思考との関係

定期思考は自己評価の機会である。気にかけていることは、その機会に載せる活動の間隔である。作業開始はどちらでもない。

| | 定期思考 `wake_policy` | 気にかけていること `standing_concerns` |
| --- | --- | --- |
| 役割 | 自己評価の機会 | その機会に載せる活動の間隔 |
| 起こすもの | `background_thinking` | 作業ではない。due なら盤面に載る |
| 間隔の意味 | 次に考えるまでの間隔 | 同じ活動を候補に出す最短間隔。着手したときだけ進む |
| 持たないもの | 手段、MCP、Skill | `mcp_server_id`、`skill_ids`、実行指示 |

通常の定期思考が機会をくれるなら、due な関心はそこに乗る。
気にかけていることの間隔は `background_thinking` を起こさない。`wake_policy.mode` が `interval` でないときも起こさない。
`min_interval_seconds` が `wake_policy.interval_seconds` 以下なら、到来した定期思考ごとに、due なら盤面に載る。それより長いときは、前回関わってからその秒数が経つまでの定期思考には載らない。
新しい作業サイクルや別の `source_kind` は作らない。

思考前観測には載せない。観測は感覚、この設定は活動の間隔である。

## やらないこと

- 関心の間隔で `background_thinking` を起こすこと
- 進行中の run がある活動を、間隔の経過だけで再び候補に出すこと
- 指定 MCP / Skill の定期実行チェック
- due で server が `autonomous_run` を作ること
- 設定から偽の `drive_state` を作ること
- 投稿や確認の義務化
- tool 名表による関与判定
- 届いた働きかけを見る専用の観測デーモン
- MCP 定義や Agent Skill source に向きや自発の項目を置くこと
