# 観測入力 API

API `0.11.0` のwire正本である。認証・envelope・本文上限は [共通ルール](共通ルール.md)、意味・処理順は [周辺環境](../runtime/周辺環境.md) を参照する。
この文書内のobjectは、既存objectの追加fieldを除き許可キーだけを受理する。

## 設定: `/api/config/environment/editor-state`

### `GET`

環境の場所定義、sensor source、画像の鮮度方針を返す。
camera の設定本体は現行の camera-source API に置き、この bundle へ複写しない。

```json
{
  "ok": true,
  "data": {
    "image_max_age_seconds": 300,
    "places": [
      {"place_ref": "place:workroom", "display_name": "作業部屋"}
    ],
    "sensor_sources": [
      {
        "sensor_source_id": "sensor_source:workroom",
        "display_name": "作業部屋センサー",
        "producer_client_id": "sensor-workroom",
        "enabled": true,
        "place_ref": "place:workroom",
        "source_owner": "self",
        "max_age_seconds": 120,
        "channels": [
          {"channel_id": "temperature", "display_name": "温度", "kind": "measurement", "value_type": "number", "unit": "degC"},
          {"channel_id": "humidity", "display_name": "相対湿度", "kind": "measurement", "value_type": "number", "unit": "%"},
          {"channel_id": "motion", "display_name": "人感の最終反応", "kind": "event", "value_type": null, "unit": null}
        ]
      }
    ]
  }
}
```

### `PUT`

request body は GET の `data` と同じ完全定義とする。検証後に一つの取引で全体置換し、同じ response を返す。
`image_max_age_seconds / places / sensor_sources` は必須とする。
新規初期化時の定義は `image_max_age_seconds=300`、二つの一覧は空とする。
保存済み定義の欠落や不正値をこの初期値へ補完しない。

| 項目 | 契約 |
| --- | --- |
| `place_ref` | `place:` で始まる非空 ID。定義内で一意 |
| `sensor_source_id` | `sensor_source:` で始まる非空 ID。定義内で一意 |
| `channel_id` | source 内で一意の非空 ID |
| `display_name` | 非空文字列。名称は変更でき、ID は同じ資源の間で維持 |
| `producer_client_id` | 非空の安定 client ID |
| `enabled` | boolean |
| source の `place_ref` | 登録済み場所参照、または未設定の `null` |
| `source_owner` | `self / user_environment` |
| `image_max_age_seconds / max_age_seconds` | boolean を除く正の整数 |
| `channels` | 1 件以上。全 enabled source の channel 総数は設計の件数境界に従う |
| channel の `kind` | `measurement / event` |
| measurement の `value_type / unit` | `number` と非空単位、または `boolean` と `null` |
| event の `value_type / unit` | 両方 `null` |

単位は登録した機械用文字列と完全一致で照合する。コードが名称から単位を推定しない。
source / channel の削除、無効化、場所・所有境界・型・単位・producer・鮮度設定の変更時は、対象の runtime 最新値と比較文脈を失効させる。
表示名だけの変更では原観測 ID を変えない。保存済み経験は当時の metadata を保持する。
camera が参照中の場所の削除は拒否する。参照を明示的に変更した後に削除する。
無効 source への報告は受理しない。

この API に機器のアカウント、接続 URL、token は含めない。
実機 connector 固有の接続・秘密値の設定契約は、機器選定時に既存の connector 配置方針に従って定義する。
この API は vendor payload の汎用 JSON 保存欄を持たない。

## camera-source の場所

現行の camera-source の読み取り、編集、editor-state 定義に `place_ref` を追加する。
編集する camera 定義はこの field を必須とし、登録済み参照または `null` を受理する。
source の名前、connector client、所有境界、認証値は引き続き camera-source の設定を正とする。
場所を削除する処理と camera 設定更新は、同じ config-store の参照整合性検証を使う。
desktop / virtual の物理場所はこの変更では設定せず、`place_ref=null` とする。

## センサー入力: `POST /api/observations/sensors`

登録済み connector が、機器の最新の報告を送る。
一回の request は一つの source、channel ごとに最大一件の報告とする。
body の上限は 32 報告とし、channel の重複を受理しない。
この endpoint は観測 runtime を更新するだけで、LLM 呼び出しや wake を開始しない。

```json
{
  "client_id": "sensor-workroom",
  "sensor_source_id": "sensor_source:workroom",
  "samples": [
    {
      "sample_id": "9c249a47-0813-4f09-b584-b382191e76e8",
      "channel_id": "temperature",
      "occurred_at": "2026-10-28T14:30:00+09:00",
      "status": "succeeded",
      "payload": {"kind": "measurement", "value": 26.2, "unit": "degC"},
      "error_code": null
    },
    {
      "sample_id": "5852ae66-aad9-44d9-99ec-99f6a90a1b81",
      "channel_id": "motion",
      "occurred_at": "2026-10-28T14:30:00+09:00",
      "status": "succeeded",
      "payload": {
        "kind": "event",
        "monitoring_started_at": "2026-10-28T09:00:00+09:00",
        "last_occurred_at": "2026-10-28T14:29:58+09:00"
      },
      "error_code": null
    }
  ]
}
```

全 field を必須とする。`samples` は 1 件以上。
`sample_id` は producer が新しい報告ごとに発行する UUID であり、再送時は同じ ID と本文を使う。
同一性の namespace は source / channel とする。
`occurred_at` は成功した取得・報告、または失敗した取得試行の時刻とする。
成功の場合、この時刻が server 内部の `observed_at` になる。
失敗には成功した外界観測を作らず、試行時刻を取得状況へ記録する。
server が受信開始時刻を `received_at` として付ける。
将来の `occurred_at` を受理せず、受信時刻で上書きしない。
`monitoring_started_at <= last_occurred_at <= occurred_at` とし、最後の反応が無い場合は `last_occurred_at=null` にする。
監視開始時刻も `occurred_at` 以下とする。

| `status` | `payload` | `error_code` |
| --- | --- | --- |
| `succeeded` | 登録 kind に合う measurement または event | `null` |
| `failed` | `null` | `source_unavailable / acquisition_failed / invalid_device_value` |

自由文の機器例外、接続先、vendor の raw payload は送信欄にしない。
number型measurementの`payload`には任意で`change`を添えられる。boolean型とeventには添えない。未提供の場合は分類情報のない観測として扱い、分類を補完しない。提供時は次の全fieldを必須とする。

```json
{
  "kind": "measurement",
  "value": 24.6,
  "unit": "degC",
  "change": {
    "pattern": "rapid_change",
    "previous_value": 24.0,
    "delta": 0.6,
    "elapsed_seconds": 10.0
  }
}
```

`pattern`は`initial / steady / changing / rapid_change`。`initial`では残り3fieldをすべて`null`とする。それ以外では有限のnumberを必須とし、`elapsed_seconds > 0`、`value - previous_value`と`delta`の整合を検証する（浮動小数点の比較許容差は相対・絶対とも`1e-9`）。差はmeasurementと同じ単位である。`change=null`や不完全なobjectは受理しない。分類の意味境界は[周辺環境](../runtime/周辺環境.md#測定上の変化情報)を参照する。

認証後、`client_id` と登録された `producer_client_id` の一致を照合する。
これは既存の共有 token による信頼済み接続の範囲での照合であり、client 別の認証資格を新設するものではない。
場所・所有境界・表示名・有効期限は request の自己申告から取得せず、server 設定から解決する。

request 内の全報告を検証してから runtime lock 内で一括適用する。
検証に使った source 設定の世代を適用時にも照合し、設定変更と受信処理の競合では旧設定の値を適用しない。
この場合は `sensor_source_changed` として request 全体を拒否する。
直近と同一 sample ID・同一本文の再送は `duplicate` として成功し、観測時刻と有効期限を更新しない。
直近と同一 sample ID で本文が違う場合は競合とする。
別 sample の `occurred_at` は、その channel に採用済みの成功・失敗報告より後であることを必須とする。
逆転・同時刻の別 sample は競合とし、過去値で最新状態を戻さない。
process 再起動後の runtime は未取得なので、最初の報告として検証する。
同じ sample から作る観測 ID は再起動後も安定させる。
event channel で監視開始時刻が同じ場合、最後の反応時刻を前の値より戻したり、値がある状態から `null` に戻したりしない。
監視を再開始した場合は新しい監視開始時刻を報告する。監視開始時刻自体も前の報告より戻さない。

有効期限切れの報告も受信内容の監査として受理できるが、runtime の利用可能値は `stale` とする。
`failed` は HTTP で観測報告を受理した成功と、機器の取得失敗を区別する。

```json
{
  "ok": true,
  "data": {
    "sensor_source_id": "sensor_source:workroom",
    "results": [
      {
        "sample_id": "9c249a47-0813-4f09-b584-b382191e76e8",
        "channel_id": "temperature",
        "acceptance": "accepted",
        "observation_id": "observation:936efb68-21d7-5cec-8edb-d23bfab0ac57"
      },
      {
        "sample_id": "5852ae66-aad9-44d9-99ec-99f6a90a1b81",
        "channel_id": "motion",
        "acceptance": "accepted",
        "observation_id": "observation:286b5d9d-791f-5797-a11d-90ecb8226c33"
      }
    ]
  }
}
```

`results` は入力順に同じ件数を返す。
`acceptance` は `accepted / duplicate`。`observation_id` は成功報告では安定した server ID、失敗報告では `null` とする。

## 既存画像入力の変更

### `vision.capture` result

`result` に `captured_at` を追加する。
画像を一件含む成功 result では offset 付き撮影時刻を必須とする。
画像のない失敗・正常スキップでは `null` を必須とする。
server は送信元との時計差を前後60秒まで許容し、`request.created_at - 60秒 <= captured_at <= 受信時刻 + 60秒` を受理する。両端の時刻を含む。
許容範囲外の撮影時刻は `400 invalid_capture_time` とし、応答のmessageに撮影・要求開始・受信の各時刻と許容秒数を含める。
connector は今回の要求で実際に取得した画像の時刻を付ける。
source metadata の request record との照合、画像一件の上限、既存のスキップコードは維持する。

### 会話添付・wake reference

会話の request shape と `images` の一件上限は維持する。
会話資料には server の受理時刻、参照資料には server の解決時刻を付ける。
これは資料を受け取った時刻であり、写っている出来事の撮影時刻とは表現しない。
内部 metadata に `time_basis=received / resolved` を保持する。
`captured` の camera と混同して、資料の受理時刻を現在の外界の撮影時刻にしない。
camera 観測と資料の有効期間は当回の媒体利用期間を表し、資料内の出来事の新しさを保証しない。

## inspection

`GET /api/inspection/current-state` に `surroundings` を追加する。
読み取り時刻、source / channel / 場所、現在の取得状態、測定値・単位、監視・反応時刻、観測時刻、有効期限を返す。
この読み取りは新しい観測や LLM 呼び出しを行わない。
画像はその場で取得・保存せず、最新の保存済み視覚説明を記録時刻とともに返す。
この保存済み説明を live camera の成功状態として表示しない。

`surroundings` は `generated_at / observations / source_reports / recent_visual_records` を持つ。`observations` は有効なセンサー報告であり、カメラの当回入力を保持する LLM 用 `surroundings` とは別の inspection view である。
各観測は `observation_id / source_ref / channel_id / origin_kind / source_kind / source_label / source_owner / place_ref / place_name / observed_at / received_at / expires_at / time_basis / observed_persons / kind / payload` を持つ。測定値の `payload` は受信時の種別に従い、時刻は offset 付き timestamp で返す。
`source_reports` は `source_ref / channel_id / source_label / place_ref / status / status_at / error_code` を持つ。
`recent_visual_records` は `visual_observation_id / observed_at / source_kind / source_label / vision_source_id / detailed_summary_text` の一覧であり、保存された過去の観測として表示する。

`GET /api/inspection/cycles/{cycle_id}` の trace に設計で定めたsnapshot、観測参照、入力解釈を追加する。
既存 endpoint の外側の response envelope と人物の応答先は維持する。
raw image、base64、機器の接続先、認証値を返さない。

## 追加エラー

| HTTP | `error.code` | 条件 |
| --- | --- | --- |
| `400` | `invalid_environment_config` | 定義の型・必須キー・参照・件数が不正 |
| `409` | `environment_place_in_use` | camera が参照中の場所を削除 |
| `400` | `invalid_sensor_samples` | 報告の shape、UUID、channel 重複、上限が不正 |
| `404` | `sensor_source_not_found` | 未登録 source |
| `409` | `sensor_source_disabled` | 無効 source |
| `409` | `sensor_source_client_mismatch` | producer client と不一致 |
| `409` | `sensor_source_changed` | 検証後に source 設定が変更された |
| `400` | `invalid_sensor_channel` | 未登録 channel |
| `400` | `invalid_sensor_value` | 型、単位、kind、値の組が不正 |
| `400` | `invalid_observation_time` | timestamp 不正、未来時刻、反応時刻の矛盾 |
| `409` | `sensor_sample_conflict` | 直近と同じ sample の本文不一致 |
| `409` | `sensor_sample_out_of_order` | 別 sample の時刻が採用済み報告以前 |
| `400` | `invalid_capture_time` | 成功画像の撮影時刻が欠落または要求・受信時刻と不整合 |

複数報告の一件でも不正なら、request 全体を適用せずエラーを返す。
この wire の API 互換版は `0.11.0` とする。
変更後に撮影時刻を持たない旧 result を補完して受理するレイヤーは作らない。
