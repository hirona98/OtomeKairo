# 状態と設定

## この文書の境界

この文書は、状態 API と設定 API の path、method、認証、request / response、error code を正本にする。
設定定義の意味規則は、人格設定を [../configuration/人格設定詳細.md](../configuration/人格設定詳細.md)、モデルプリセットを [../configuration/モデルプリセット詳細.md](../configuration/モデルプリセット詳細.md)、設定変更単位を [../configuration/設定変更.md](../configuration/設定変更.md) に置く。
秘密値の表示境界、`editor-state` の例外、audit の方針は [../integration/接続と権限境界.md](../integration/接続と権限境界.md) を正とする。
この文書では、各 endpoint が返す field と秘密値の mask 形式だけを定める。

## 状態面

### `GET /api/status`

- 認証: 必要
- 役割: 運用に必要な設定スナップショットとランタイム要約を返す

response:

```json
{
  "ok": true,
  "data": {
    "settings_snapshot": {
      "selected_persona_id": "persona:default",
      "selected_memory_set_id": "memory_set:default",
      "wake_policy": {
        "mode": "disabled",
        "interval_seconds": 300
      },
      "selected_model_preset_id": "model_preset:default",
      "pre_send_check_model_preset_id": "model_preset:pre_send_check",
      "thinking_speech_level": 5,
      "selected_conversation_display_name_id": "conversation_display_name:tanaka"
    },
    "runtime_summary": {
      "connection_state": "ready",
      "background_thinking_scheduler_active": false,
      "autonomous_run_scheduler_active": true,
      "ongoing_action_exists": false,
      "active_autonomous_run_count": 0,
      "paused_autonomous_run_count": 0,
      "memory_job_worker_active": true,
      "visual_daily_worker_active": true,
      "pending_memory_job_count": 0,
      "memory_job_in_progress": false,
      "visual_daily_in_progress": false
    }
  }
}
```

- `background_thinking_scheduler_active` は、server 内の定期思考スケジューラが稼働中で、かつ `wake_policy.mode=interval` のとき `true` を返す
- `autonomous_run_scheduler_active` は、server 内の due `autonomous_run` スケジューラが稼働中のとき `true` を返す
- `ongoing_action_exists` は、未失効の `ongoing_action` が 1 件あるとき `true` を返す
- `active_autonomous_run_count` は、active、waiting_timer、waiting_result の `autonomous_run` 件数を返す
- `paused_autonomous_run_count` は、paused の `autonomous_run` 件数を返す
- `memory_job_worker_active` は、embedding 更新と `reflective consolidation` を処理する background worker が稼働中のとき `true` を返す
- `visual_daily_worker_active` は、視覚記録の日次整理 worker が稼働中のとき `true` を返す
- `pending_memory_job_count` は、未完了の記憶後段 job 数を返す
- `memory_job_in_progress` は、worker が現在 1 件の job を処理中のとき `true` を返す
- `visual_daily_in_progress` は、日次視覚整理 worker が現在 1 件の digest を処理中のとき `true` を返す
- `drive_state`、`autonomous_run`、`ongoing_action` の生 row は `GET /api/status` へ含めない

`GET /api/status` は日次視覚 digest の詳細を返さない。
日次視覚整理の稼働有無だけを返し、digest の件数や要約確認は inspection API の責務にする。

### `POST /api/config/update-wake-policy`

request:

```json
{
  "wake_policy": {
    "mode": "interval",
    "interval_seconds": 15,
    "observations": [
      {
        "observation_id": "observation:main_desktop",
        "enabled": true,
        "capability_id": "vision.capture",
        "input": {
          "vision_source_id": "vision_source:console:desktop",
          "mode": "still"
        }
      },
      {
        "observation_id": "observation:room_camera",
        "enabled": true,
        "capability_id": "vision.capture",
        "input": {
          "vision_source_id": "vision_source:console:camera",
          "mode": "still"
        }
      }
    ]
  }
}
```

`thinking_speech_level` は、`background_thinking` の各判断で短い独話として前へ出る自然さを見積もるときの補助レベルである。
値は `1..10` の整数で、`1` は控えめ、`5` は標準、`10` は短い独話としてまとまる場合に前へ出やすい基準を表す。
既定値は `5` である。
`wake_policy` は server 内の定期思考スケジューラに適用する。
外部からの `POST /api/wake` は `wake_policy` の due 判定と `wake_policy.observations` を使わず即時に実行する。
`wake_policy.interval_seconds` は有効状態に関係なく必須であり、正の整数とする。
`wake_policy.interval_seconds` の既定値は `300` 秒である。
`wake_policy.mode=disabled` のとき、server は定期思考スケジューラによる起床を実行しない。
`wake_policy.mode=disabled` の間も `wake_policy.interval_seconds` を保持し、次に有効化したときの実行間隔として使う。
`wake_policy.mode=disabled` のときも、server は `wake_policy.observations` を保持する。
`wake_policy` の間隔単位は秒で統一する。
`wake_policy.observations` は任意配列である。
`wake_policy.observations[].enabled=false` の項目は取得しない。
`wake_policy.observations[].capability_id` は `vision.capture` のみを許可する。
`wake_policy.observations[].input` は `vision.capture.input` と同じ schema である。
OtomeKairo の視覚として採用した `VisionSource(kind=camera, source_owner=self)` は、`camera_source.enabled=true` のとき定期思考処理が観測対象へ動的に含める。
camera source の有効/無効切り替えは `wake_policy.observations` を書き換えない。
保存済みの `wake_policy.observations[].input.vision_source_id` が接続中 source に存在しない場合、server は `vision_source_id` 末尾の source kind と接続中 source の `kind/default_for` から一意に再解決する。
再解決できた場合、server は実際の `vision.capture` request に再解決後の `vision_source_id` を入れる。
再解決候補が 0 件または複数件の場合、server は observation を失敗として扱う。
server は定期思考で `wake_policy.interval_seconds` ごとに enabled observation を順番に取得する。
visual capture を含む enabled observation が無効状態から有効になった直後の初回だけ、server は 5 秒待ってから最初の観測を行う。
この初回待ちでは、直前の `last_wake_at` や一時失敗の再試行待ちを消費せず、5 秒経過後に必ず最初の観測へ進む。
visual capture の取得結果は画像意味理解へ通し、同じ `visual_observation` 呼び出しで `change_state / change_basis / change_reason_summary` を生成し、視覚記録と `world_state` に反映してから 1 回だけ wake 判断を行う。
visual observation は wake 判断へ渡す。`first_seen / changed` は wake 判断へ進む前景シグナル、`stable` は現在状態の継続シグナル、`same_as_recent_speech` は直近発話との重複シグナルとして扱い、発話可否は観測差分だけで決めず、`speech / noop / pending_intent` の意味判断で決める。
反復抑制の材料は `same_as_recent_speech` と同一 `dedupe_key` の直近発話で扱う。
`change_state` の意味判定は `visual_observation` の構造化出力を正とする。
`wake_policy` は `mode`、`interval_seconds`、`observations` 以外の field を持たない。

`selected_conversation_display_name_id` は存在する呼ばれ方定義のIDとする。
serverは選択した定義の `display_name` に敬称を追加せず、`participants[].display_name`へ文字列全体を渡す。
新規既定状態の `selected_conversation_display_name_id` は既定呼ばれ方定義を指す。

### 呼ばれ方定義 API

- `GET /api/config/conversation-display-names`: 定義一覧を返す
- `POST /api/config/conversation-display-names`: 定義を追加する
- `PUT /api/config/conversation-display-names/{conversation_display_name_id}`: 表示名を変更する
- `DELETE /api/config/conversation-display-names/{conversation_display_name_id}`: 定義を削除する

作成と更新の request は `{"display_name":"田中さん"}` とする。
`display_name` は前後空白を除いた非空文字列とし、定義間で重複させない。
呼ばれ方定義は1件以上を保つ。
現在設定が参照している定義を削除するとき、server は残りの定義の1件へ選択を付け替えてから削除する。
最後の1件、または音声話者が参照している定義の削除は `conversation_display_name_in_use` で拒否する。
新規既定状態は `display_name=マスター` の呼ばれ方定義を1件持つ。

### `PUT /api/config/avatar-speech/editor-state`

- 認証: 必要
- 役割: アバター音声プリセット群、現在選択、マイク設定、音声出力設定を bundle 単位で全体置換する
- request body は `selected_avatar_id`、`microphone_settings`、`audio_output_settings`、`avatars` だけを持つ
- `avatars` は 1 件以上を必須とし、`avatar_id` の重複を許可しない
- `selected_avatar_id` は `avatars[].avatar_id` に存在する値を必須とする
- 全 field を検証してから 1 transaction で保存し、部分更新しない
- response は `GET /api/config/avatar-speech/editor-state` と同じ shape を返す
- `avatars[].stt.api_key` と `avatars[].tts.aivis_cloud_config.api_key` の実値を返す
- write を認証済み設定編集操作として audit に残す
- response body を server log へ出さない

request body は `GET /api/config/avatar-speech/editor-state` の `data` と同じ shape にする。

field 制約:

- `avatar_id` は `avatar:` で始まり、各 entry の識別子と一致する
- `display_name` は空ではない文字列にする
- `microphone_settings.input_source` は `local_microphone / console_microphone / web_microphone` のいずれかにする
- `microphone_settings.local_input_device` は `null` または `host_api / name` だけを持つ object にする
- `microphone_settings.local_input_device.host_api / name` は前後空白を除いた非空文字列にする
- `microphone_settings.console` は `null` または `client_id / input_device` だけを持つ object にする
- `microphone_settings.console.client_id` は前後空白を除いた非空文字列にする
- `microphone_settings.console.input_device` は `null` または `device_id / name` だけを持つ object にし、object の各値を前後空白を除いた非空文字列にする
- `input_source=console_microphone` では `console` と `console.input_device` を必須とする
- `input_source=web_microphone` の入力deviceはブラウザのorigin単位で保持し、この設定bundleへ含めない
- `microphone_settings.vad_probability_threshold` は `0.1..0.9` の数値にする
- `microphone_settings.speaker_recognition_threshold` は `0.1..0.9` の数値にする
- `audio_output_settings.destination` は `otomekairo / cocoro_console / browser` のいずれかにする
- `audio_output_settings.local_output_device` は `null` または `host_api / name` だけを持つ object にし、各値を前後空白を除いた非空文字列にする
- `stt.engine` は `amivoice` にする
- `stt` は `enabled` / `engine` / `profile_id` / `api_key` だけを持つ。`wake_words` を含む場合は `invalid_avatar_stt_fields` で拒否する
- `stt.profile_id` は空文字または `[A-Za-z0-9_-]+` にし、`__` で始まる値を許可しない
- `tts.engine` は `voicevox`、`style-bert-vits2`、`aivis-cloud` のいずれかにする
- `voicevox_config.endpoint_url` は前後空白を除いた非空文字列にする（優先接続先）
- `voicevox_config.secondary_endpoint_url` は文字列とし、空文字を許可する（サブ接続先。空なら単一接続）
- `voicevox_config.secondary_endpoint_url` が非空のとき、正規化後の URL が `endpoint_url` と同一であってはならない
- `voicevox_config.output_sampling_rate` は `16000`、`22050`、`24000`、`44100`、`48000` のいずれかにする
- `voicevox_config.speed_scale` は `0.5..2.0`、`pitch_scale` は `-0.15..0.15` にする
- `voicevox_config.intonation_scale` と `volume_scale` は `0.0..2.0` にする
- `voicevox_config.pre_phoneme_length` と `post_phoneme_length` は `0.0..1.5` にする
- `aivis_cloud_config.speaking_rate` は `0.5..2.0` にする
- `aivis_cloud_config.emotional_intensity`、`tempo_dynamics`、`volume` は `0.0..2.0` にする
- `aivis_cloud_config.pitch` は `-1.0..1.0` にする
- `aivis_cloud_config.output_bitrate` は WAV 固定のため `0`、`output_sampling_rate` は `1` 以上の整数にする

`avatar` は人格設定と人物の定義から独立した音声設定の単位である。
`avatar-speech` bundle の利用先は設定 UI と OtomeKairo の音声入出力処理であり、client は TTS provider の設定と資格を使用しない。
LLM prompt は既存の人格設定、記憶、現在入力から構築する。
音声入力、話者登録、話者識別の wire は [audio_stream.md](audio_stream.md)、意味規則は [../audio/音声入力と話者識別.md](../audio/音声入力と話者識別.md) を正とする。
音声出力先の意味規則は [../audio/音声出力.md](../audio/音声出力.md) を正とする。

### CocoroShellへの実行時設定配送

CocoroShellはOtomeKairo APIを直接呼び出さない。
CocoroConsoleはOtomeKairoから取得済みの端末設定をCocoroShell専用の起動時設定へ変換する。
このローカルAPIはOtomeKairoの外部APIではなく、CocoroConsoleとCocoroShellの間だけで使用する。

起動順序を次に固定する。

1. CocoroConsoleがOtomeKairoの設定を取得する
2. CocoroConsoleが起動単位のsession tokenを生成し、ローカルAPIの待受を開始する
3. CocoroConsoleがPlayerへローカルAPI URLとsession tokenを環境変数で渡す
4. Unity Editorでは、CocoroShellが同一OSユーザーに限定した名前付きパイプからローカルAPI URLとsession tokenを取得する
5. CocoroShellがシーン開始前に実行時設定を取得して検証する
6. 取得または検証に失敗した場合、CocoroShellは起動を中断する

#### `GET /api/shell/runtime-config`

- 提供主体: CocoroConsoleのloopbackローカルAPI
- 認証: 起動単位のBearer session token
- 役割: CocoroShellが一回の起動で使用する設定snapshotを返す
- responseは`clientId`、`shellApiPort`、`display`、選択済み`avatar`、`motion`を含む
- `motion.selectedAnimationSetId`は`motion.animationSettings[].animationSetId`を参照する
- STT設定、TTS設定、音声providerの資格はresponseへ含めない
- OtomeKairoのconsole tokenはCocoroShellへ渡さない
- response bodyとBearer session tokenをログへ出さない

#### `POST /api/audio/playback`

- 提供主体: CocoroShellのloopbackローカルAPI
- 認証: 起動単位のBearer session token
- 役割: OtomeKairoで合成済みのWAVをCocoroShellで再生し、アバターの発話動作とlip syncへ接続する
- request bodyは`Content-Type: audio/wav`のraw binaryとする
- request bodyは32 MiB以下のRIFF/WAVEとし、PCM 16-bitまたはIEEE float 32-bitのsampleを含める
- CocoroShellは音声合成を実行しない

CocoroConsoleはevent streamの`assistant_audio`に続くbinary WAVを受信する。
CocoroConsoleは`CocoroShell` processが存在する場合に同じWAVを`POST /api/audio/playback`へ送る。
Unity Editor実行時は`CocoroShell` processが存在しないため、`GET /api/status`のHTTP到達性をShell起動中の判定に使う。
Shell起動中と判定した後のstatus異常またはWAV配送失敗では、CocoroConsoleはエラーを公開し、直接再生へ切り替えない。
`CocoroShell` processが存在せずloopback APIにも到達できない場合、CocoroConsoleは受信済みWAVをローカル音声出力で直接再生する。

Unity Editor用の名前付きパイプは設定配送APIではなく起動情報のIPCである。
パイプ名は`CocoroAI.CocoroShell.EditorBootstrap.v1`とし、同一OSユーザーのprocessだけが接続する。
このIPCはローカルAPI URLとsession tokenだけを返し、実行時設定は上記HTTP APIから取得する。

#### `PUT /api/shell/avatar-position`

- 提供主体: CocoroConsoleのloopbackローカルAPI
- 認証: 起動単位のBearer session token
- 役割: CocoroShellが確定したウィンドウ位置をCocoroConsole経由で端末設定へ保存する
- request bodyは有限数値の`x`と`y`を持つ
- CocoroConsoleは`display.avatar_position_x / avatar_position_y`へ反映し、OtomeKairoの端末設定を保存する

CocoroShellは`UserData/Setting.json`と`UserData/AnimationSettings.json`を読み書きしない。
実行中の部分更新と設定リロードAPIは設けず、設定変更はCocoroShellの再起動で反映する。

### `PUT /api/config/mcp-servers/{mcp_server_id}`

- 認証: 必要
- 役割: 指定した MCP server 定義を全体置換で作成または更新する
- request body は有効/無効、transport 固有接続定義、送信前チェック方針、有限 MCP セッション方針を受ける
- response は mask 形式の MCP server 定義を返す

request:

```json
{
  "enabled": true,
  "pre_send_check_enabled": true,
  "command": "uvx",
  "args": ["estat-mcp-server"],
  "cwd": null,
  "env": {
    "E_STAT_APP_ID": "..."
  },
  "autonomous_session": {
    "enabled": false,
    "background_enabled": false,
    "min_interval_seconds": 3600,
    "max_tool_calls": 10
  }
}
```

`mcp_server_id` は path の値を保存する。
`connector_kind` は `mcp_client` だけを許可する。
`client_id` は省略時に `mcp-client-connector-main` として扱う。
`transport` は省略時に `stdio` として扱う。
`transport=stdio` は `command / args / cwd / env` だけを持つ。
`transport=streamable_http` は userinfo と fragment のない HTTPS `url` と `headers` だけを持つ。
両 transport の field を混在させず、未知 field と MCP protocol 管理 header を拒否する。
`env / headers` は秘密設定値として保持する。
`pre_send_check_enabled` は必須 boolean とする。
読み取り中心の MCP は `false`、投稿や外部書き込みを含む MCP は `true` を使う。
既定の `elyth` 雛形は `pre_send_check_enabled=true`、`e-stat` 雛形は `false` である。

ELYTH Remote MCP の設定例:

```json
{
  "enabled": true,
  "pre_send_check_enabled": true,
  "transport": "streamable_http",
  "url": "https://elythworld.com/api/mcp/remote",
  "headers": {
    "Authorization": "Bearer ..."
  },
  "autonomous_session": {
    "enabled": true,
    "background_enabled": true,
    "min_interval_seconds": 3600,
    "max_tool_calls": 10
  }
}
```

ELYTH は普通の MCP server として扱い、この URL、header、送信前チェック値は設定例である。`elyth` という server id、特定 URL、Bearer 形式に対する server 側の特別規則は設けない。一般規則として disabled の定義では空の header 値を許し、enabled の Streamable HTTP 定義では登録した全 header 値を空でない文字列にする。

`autonomous_session` は全 MCP server で必須の exact shape とし、`enabled / background_enabled / min_interval_seconds / max_tool_calls` だけを持つ。`min_interval_seconds / max_tool_calls` は正の整数、`background_enabled=true` は `enabled=true` を必要とする。これは ELYTH 固有設定ではなく、任意の MCP server に同じ意味で適用する。開始、call 消費、終了の契約は [../runtime/autonomous_run.md](../runtime/autonomous_run.md#有限-mcp-セッション) を正とする。

- この endpoint は [../integration/接続と権限境界.md](../integration/接続と権限境界.md) の秘密値返却例外として、該当 camera source の `connection.host`、`connection.camera_username`、`connection.camera_password` の実値を返す
- response の `camera_source` は watcher 実行に必要な識別子、種別、表示名、接続情報だけを返し、能力側の有効状態 `enabled` を返さない
- response body を server log へ出さない

現行の設定正本は `config.db` である。
`avatars`、`microphone_settings`、`audio_output_settings`、`camera_sources`、`mcp_servers`、`agent_skill_sources` は `config.db` に保存する。
記憶、events、cycle trace、world_state は `memory.db` に保存する。
