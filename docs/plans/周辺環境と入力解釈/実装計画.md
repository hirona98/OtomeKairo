## 実装した範囲

- 共通の不変snapshot、種別付き観測、取得状態、当回だけのmedia bundle。
- 場所・sensor source・鮮度の設定、最新報告のruntime、認証された環境設定・sensor報告API。
- 入力解釈一回で観測説明・意味上の変化・想起方針・回答根拠契約を生成し、同じ画像と測定値を行動判断へ渡す。
- 会話、定期思考、API起床、通常の能力結果、自律stepへの接続。観測がないstepは追加の観測解釈を行わない。
- 世界状態のsource/channel単位の候補、根拠の鮮度上限、失敗・設定変更時の現在値の失効。
- 観測を先に保存し、入口の見送りや後続失敗でも保持する。sensor eventの重複防止と記憶集合のclone/delete。
- 当回観測の想起検索からの除外、隔離した自身の活動から原観測・派生状態・比較資料を除く処理。
- inspectionとtraceの媒体を含まない観測表示。独立visual_observation生成経路の削除。
- API 0.11.0、config schema 21、cameraのplace_ref、capture結果のcaptured_at。TapoとCocoroConsoleの送信元を更新。

実機の機種・接続方式が未選定のため、vendor固有のdriverは範囲外とし、模擬producerで受信から判断まで確認した。

## 2026-11-02 取得経路の修正

運用traceでデスクトップ取得の45秒timeoutと、その直後のcamera取得の遮断を確認した。
CocoroConsoleの画像なしresultで、JSON serializerが必須のnull撮影時刻を省略する不具合を修正した。
serverでは期間外撮影時刻の応答を契約どおりの400へ修正し、結果endpointのエラーログを有効にした。取得失敗の待機期間はsourceごとに保持する。

HTTPの結果返却から同期取得待ちの解除まで、desktop / camera、画像あり / 見送り / 失敗、時刻不正、送信失敗 / timeout / 期限切れと別sourceの取得継続を確認した。通常検証は1095件と304 subtestsが通過した（既存のDeprecationWarning 1件）。CocoroConsoleはUTF-8 / CRLFの維持とnull出力指定を確認し、指定に従いビルドしていない。

隔離したserverと通常のTapo connectorを実機cameraへ接続し、WebSocketの要求配送、撮影、HTTP結果返却、撮影時刻の受理まで約2.8秒で成功した。原画像は保存せず、運用DBと停止中のサービスは変更していない。
初回修正時点では、10/30ビルドで生じた全timeoutの直接原因は過去ログだけでは確定できなかった。その後のConsoleエラーで、送信元の時計がserverより約3秒遅れ、正常な取得結果が要求開始前の撮影として拒否されていることを確認した。

### 撮影元との時計差の許容

ユーザーの指示により、撮影時刻の前後60秒の時計差を許容する契約へ変更した。wireの範囲は[観測入力 API](../../design/api/観測入力.md#visioncapture-result)、snapshot内の扱いは[周辺環境](../../design/runtime/周辺環境.md#時刻鮮度取得状態)を正とする。
要求開始の60秒前と受信の60秒後を含めて受理し、範囲から1マイクロ秒でも外れる場合は400となることを確認する。許容した画像をsnapshotから落とさず入力解釈・判断・視覚記録まで渡し、撮影時刻を保持する。センサー報告と添付画像の未来時刻判定、画像の有効期限は維持する。
通常検証は1106件と304 subtestsが通過した（既存のDeprecationWarning 1件）。
