# 短い発話の識別改善の実装記録

## 対象

2026-11-07の[原因調査](2026-11-07_短い発話の識別調査.md)を受けて話者識別を更新した。
現行仕様の正本は[音声入力と話者識別](../../design/audio/音声入力と話者識別.md)、wireは[音声stream API](../../design/api/audio_stream.md)と[inspection](../../design/api/列挙とinspection.md)を参照する。

## 変更

- 話者モデルをERes2NetV2へ変更し、モデルが指定する正規化float・Povey窓・192次元出力を使用する。
- ONNX入出力だけでなく、前処理のmetadataも起動時に検証する。
- 重みとONNX sessionをprocess内で共有し、runtimeごとの重複読み込みを防ぐ。VADのstateとcontextは共有しない。
- 同梱モデル・manifest・第三者表示を一緒に更新し、ライセンス全文を同梱する。
- 話者用PCMの前後へ取得済み音声から余白を含め、弱い語頭・語尾を保持する。VADは開始・終了のしきい値を分ける。
- 発話PCMを1つのバッファで保持し、STT用と話者用のviewを切り出す。paddingを発話時間や登録条件へ算入しない。
- runtimeのモデル表示を汎用の`speaker_embedding`へ変更する。
- 保存済み登録が別モデルの場合、設定画面に再登録の理由と操作案内を表示する。

保存済みの人物・名前・記憶は維持する。
別モデルの登録は照合から除き、利用者が同じ人物への再登録を完了した時点で新しい特徴量へ原子的に置き換える。
DBの変換処理や旧モデルへの切替処理は追加していない。
保存済みの識別しきい値は維持する。
新規設定の既定値と初期表示は新モデルに合わせて0.4とする。

調査スクリプトは、過去の比較を再現するためのWeSpeaker baselineを明示的な引数で受け取る。
これはサーバのモデル選択とは独立したオフライン実験である。

## 検証方針

- 音声の前後余白、ヒステリシス、最短発話、15秒分割の境界をテストする。
- 同梱モデルの出力・正規化・決定性、metadata不一致時の失敗を確認する。
- 旧モデルの登録を採用しないこと、新モデルの再登録が保存・モデル再生成後も有効なことを確認する。
- 画面のテストはHTTP/API境界に留め、HTML要素や文言を固定するテストは追加しない。
- 本人の短い日本語での改善は、反映後の再登録と実発話で確認する。

## 検証結果と反映

- 通常検証は1119件・304 subtestsが通過した（既存warning 1件）。
- 旧モデルの登録がある隔離環境で、音声フレーム受信から3発話の再登録完了まで確認した。STTは呼ばれず、同じ人物に192次元の特徴量が保存された。
- 別Python processでモデルと設定DBを開き直した照合でも、保存した登録を受理した。
- 実装の前処理と独立したtorchaudioによる前処理を同じモデルで照合し、embeddingのcosine similarityが約1となることを確認した。
- 全体テストで重複読み込みによるOOMを検出したため、session共有を実装した。修正後はruntimeを100個保持しても共有speaker sessionは1個で、追加RSSは約0.06 MiBだった。VADの状態独立性もテストした。
- JavaScriptの構文、docsのローカルリンク、`git diff --check`を確認した。
- 常駐サーバーを再起動し、新モデルとlocal microphoneの稼働、VADメーター、保存済みしきい値0.4の維持をHTTP/APIで確認した。
- 保存済み旧登録は維持され、現在は`speaker_enrollment_required`となる。設定画面の同じ人物から再登録して運用を再開する。
