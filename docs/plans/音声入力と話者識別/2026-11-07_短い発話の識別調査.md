# 短い発話の話者識別調査（2026-11-07）

この記録の「現行モデル」は調査時点のWeSpeaker ResNet34を指す。
その後の修正は[実装記録](実装記録.md)を参照する。

## 結論

現行のWeSpeaker ResNet34で、短い発話ほど同一話者のcosine similarityが下がる現象を再現した。
0.8秒の公開音声では、しきい値0.4でも同一話者21区間中5区間を拒否した。2秒以上では今回の比較で拒否がなかった。
最短500msの入力に、任意内容の2秒音声から作った登録代表と同じしきい値を適用する現在の構成には、短い呼びかけの受理を安定させる根拠が不足している。

対策の第一候補は、短時間の話者識別を改善したモデルを使う構成への変更である。
ERes2NetV2を同条件で比較すると、0.8秒での拒否が5/21から0/21へ減り、今回の別人比較42件では誤受理がなかった。
ただし、この結果は中国語の公開音声3人分による小規模な比較であり、利用者の日本語・短い音声起動ワードでの採用判定には追加の実測が必要である。

この文書は調査結果と改善案の記録である。
現行の意味規則は[音声入力と話者識別](../../design/audio/音声入力と話者識別.md)、wireは[音声stream API](../../design/api/audio_stream.md)を参照する。
本調査では本番のモデル、しきい値、話者登録を変更していない。

## 実環境で確認したこと

| 項目 | 結果 |
| --- | --- |
| 前回の修正 | VADへの64 samplesのcontext付与、VAD値の保持、WeSpeakerのPCM振幅単位の修正が残っている |
| 話者登録 | 11月6日21:08の登録が保存され、256次元・有限値・L2 norm約1で読み込める |
| 保存と再読込 | DBのfloat32列とstore経由の復元値が一致する |
| モデルの再初期化 | 同じ公開PCMのembeddingが別ONNX sessionでも一致し、保存・再読込した登録との照合結果も一致する |
| モデルファイル | SHA-256は公式の`Wespeaker/wespeaker-voxceleb-resnet34`配布物と一致。LM版との取り違えはない |
| マイク | 選択先はALSAのFIFiNE K669。参照しているUSBデバイスは前回と同じで、録音ゲインも前回と同じ最大値 |
| 音量 | 試験中の入力レベルは最大約-22 dBFSまで上がり、VAD陽性も観測された |
| 直近の失敗 | 0.640秒・一致度0.305、0.832秒・一致度0.377。文字起こしは成功し、話者しきい値0.4未満で停止 |
| 長い発話 | 11.680秒・一致度0.757で受理し会話まで完了。その後も15.008秒・0.708、9.600秒・0.691を受理 |

登録消失やモデル再初期化時の数値変化は確認されなかった。
「一晩経ったこと」が一致度低下の原因かは、この記録からは確定できない。
朝晩の声、発話内容、マイク距離、周囲の音の影響は個別には測定していない。

利用者が約3秒と感じた発話に対し、サーバが扱ったVAD-positive範囲は0.832秒だった。
この差にはVADの境界、発話途中の無音、最短時間未満で破棄される区間が関係する可能性がある。
実環境の過去のPCMは保存していないため、どの音が除かれたかは遡って確定できない。
前の回答で示した「短い発話の話者照合で落ちた」は観測事実だが、実際の発話が短く切られた理由まで解明したわけではない。

## 前処理の検証

現在の`kaldi-native-fbank`による特徴量と、[公式WeSpeaker ONNX推論例](https://github.com/wenet-e2e/wespeaker/blob/master/wespeaker/bin/infer_onnx.py)に合わせた`torchaudio.compliance.kaldi.fbank`を、公開テスト音声7件で比較した。

- 特徴量の最大絶対差: 0.0008564
- embeddingのcosine similarityの最小値: 0.9999999703
- ONNX RuntimeはCPU、intra/inter-op各1 thread

現時点のWeSpeaker前処理に、今回の低一致度を説明する大きな数値差は見つからなかった。
公式の[ResNet34学習設定](https://github.com/wenet-e2e/wespeaker/blob/master/examples/voxceleb/v2/conf/resnet.yaml)は200 frames、frame shift 10msを使う。
0.5～0.8秒の任意内容の音声が、これと同じ条件の識別性能になるとは扱えない。
短い音声では登録時との音素の違いが影響する問題は、[Sub-3Secの研究](https://www.isca-archive.org/interspeech_2025/zuo25b_interspeech.html)でも扱われている。

## 比較方法

[sherpa-onnxの公開話者認識音声](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models)14ファイルを使用した。
公開ファイル名のtrain/test区分と話者名を正解ラベルにし、登録用と評価用のファイルを分離した。
音声本文の文字起こしや自然文の意味判定は行っていない。

- 3人、男性、中国語。登録用7ファイル、評価用7ファイル。
- 登録用音声はVADで前後を除き、同一人物の音声群から開始・中央・末尾の2秒を3区間取り出す。
- 各区間の正規化embeddingを平均し、再度L2正規化するものを基準とする。
- 評価用音声の最長VAD区間から、0.5 / 0.8 / 1.2 / 2.0 / 3.0秒を開始・中央・末尾で取り出す。
- 短くて指定長を取れないファイルはその長さの比較に含めない。別の長さに置き換えない。
- 各区間を正しい話者1人と別人2人に照合する。最終識別では既存のmargin 0.05も確認する。
- 同じ発話から切り出す区間には重複があり、独立した試行とはみなせない。長さごとに対象数も異なる。
- 公開音声とモデルの学習集合の重複は未検証。日本語、女性、実マイクの距離差、朝晩の変化は評価していない。
- 音声はダウンロード後もメモリ内だけで処理し、保存するJSONは出典・ハッシュ・スコア・集計値に限る。

同じしきい値0.4での記述的な比較であり、本番のFAR/FRRや適切なしきい値を推定する試験ではない。
完全な数値は[比較結果JSON](2026-11-07_比較結果.json)に保存した。
調査スクリプトの基準VAD境界は、同じ7評価ファイルを通常の`AudioSegmenter`へ20ms frameで入力し、生成される9発話の話者用PCMとbyte単位で一致することを別途確認した。

## 比較結果

### 短時間モデル

候補は[ERes2NetV2](https://arxiv.org/abs/2406.02167)の公式配布モデルをsherpa-onnxがONNXへ変換したものを使用した。
前処理は[3D-Speaker用の公式テスト](https://github.com/k2-fsa/sherpa-onnx/blob/master/scripts/3dspeaker/test-onnx.py)に合わせ、各モデルで指定された振幅単位とwindowを使用した。
候補用の登録embeddingは、同じ登録音声から候補モデル自身で新しく計算した。

| 入力長 | 正しい話者の比較数 | 現行ResNet34の拒否 | ERes2NetV2の拒否 | 別人の誤受理（現行 / 候補） |
| --- | ---: | ---: | ---: | ---: |
| 0.5秒 | 21 | 12 | 3 | 0 / 0（各42比較） |
| 0.8秒 | 21 | 5 | 0 | 0 / 0（各42比較） |
| 1.2秒 | 21 | 1 | 0 | 0 / 0（各42比較） |
| 2.0秒 | 18 | 0 | 0 | 0 / 0（各36比較） |
| 3.0秒 | 12 | 0 | 0 | 0 / 0（各24比較） |

marginも含めた識別失敗数は、この表の拒否数と同じだった。
候補でも0.5秒では拒否が残る。0.8秒での候補の別人スコア最大値は0.390であり、本試験の誤受理0件から本番の余裕を保証できない。

候補ONNXは約71.4 MB、現行は約26.5 MBで、候補の出力は192次元。
候補ファイルのSHA-256は`bf1a75b9930474cf3389ef415e6e5d38ca96fea4a3a00f7e301d080a58ee2239`。
計算時間はJSONにも記録したが、集計対象の音声長・呼出回数がモデル間で異なるため、この中央値から速度比は算出しない。

### しきい値だけを下げる場合

現行モデルの0.8秒音声について、しきい値0.4では同一話者の拒否5/21・別人の誤受理0/42だった。
0.35に下げると拒否3/21・誤受理1/42、0.3では拒否0/21・誤受理1/42になった。
3秒音声でも0.35への引下げで別人の誤受理が1/24発生した。
短い発話を通すための全体のしきい値引下げは、対策として優先しない。

### 登録方法と入力の水増し

しきい値0.4・0.8秒音声での同一話者の拒否数は、基準の2秒×3平均が5/21、各登録ファイル全体のembedding平均が4/21、登録音声を連結して1 embeddingにした場合が3/21だった。
一方、0.5秒では改善せず、登録を長くするだけで短語問題を解決する根拠にはならなかった。

登録した3 embeddingの最大値で照合する方法は0.8秒で6/21を拒否し、基準より良くならなかった。
短い特徴量を200 framesまで繰り返す方法は0.8秒で5/21、反射paddingは6/21を拒否した。
音声の情報量が増えない繰返しやpaddingを、短語対策の中心にはしない。

### VAD境界

現行と同じ境界で切り出した9発話と、前後30ms / 100msの余白、開始0.4・終了0.25のヒステリシス＋前後100msを比較した。
[Sileroの公式処理](https://github.com/snakers4/silero-vad/blob/v5.1/src/silero_vad/utils_vad.py)にも前後の余白と異なる開始・終了しきい値がある。

100msの余白で最小の同一話者一致度は0.514から0.590へ上がり、中央値は0.684から0.689へ変化した。
ただし、全案ともこの9発話では元から拒否0件であり、認識失敗の解消を実証した結果ではない。
別人の最大スコアも0.308から0.334へ上がるため、余白の追加が常に良いとは扱わない。
ヒステリシスを加えた効果はこの音声群では小さく、「3秒が0.8秒になる」現象は再現していない。

## 改善の進め方

1. **実マイクの同じ発話で原因を分離する。** 明示的な診断sessionで音声をメモリ内だけに保持し、全体、0.8秒・1.2秒部分、現行VAD切出し、余白付き切出しを比較する。発話中のVAD値、PCMのsample数・peak・RMS・clipping率、登録との一致度だけを残す。診断の音声を会話や登録へ混ぜず、session終了時に破棄する。これにより、モデルの短時間性能と実環境の切出し損失を分離できる。
2. **ERes2NetV2を第一候補として実環境で比較する。** 利用者本人の日本語、普段の音声起動ワード、別時刻・距離の音声、ラベルが明らかな別人・再生音声で比較する。本番採用の条件は、同じ評価音声で短語の拒否が減り、別人の誤受理が増えず、CPU処理時間が発話キューの運用を満たすこととする。
3. **VAD境界を補助的に改善する。** 実マイクの対比較で効果が確認できれば、話者識別用の前後余白と開始・終了しきい値を意味規則の正本へ反映する。登録と通常照合へ同じ切出し規則を適用する。
4. **登録品質としきい値を評価音声で決める。** 任意の2秒発話3件だけで実用性能を満たすかを再評価し、異なる内容・時刻・距離を含む登録方法を検討する。しきい値はモデルごとに別人も含む実測で決める。

モデルを変更する場合は、model file・manifest・ID・特徴量契約・embedding次元の検証を一緒に更新する。
候補の振幅単位は正規化float、windowはPoveyで、現行WeSpeakerのPCM振幅単位・Hammingと区別する。
採用ファイルの出典とライセンスも確定したうえでリポジトリへ同梱する。
モデル切替時は既存人物の`person_ref`を保って明示的に再登録し、旧モデルのembeddingを新モデルとの照合へ流用しない。
CPUでの単一モデル運用、発話ごとの話者確定、音声を保存しない境界は現行正本に従う。

今回の結果から、長く話す運用だけを最終的な解決策とはしない。
同時に、候補モデルの公開音声での改善だけを根拠に本番モデルを置き換えることもしない。

## 再現

[調査スクリプト](../../../scripts/analyze_speaker_recognition.py)は通常サーバと独立して動作する。
公開音声のSHA-256を固定し、同じ出典が変更された場合は失敗する。

```bash
curl -fL 'https://huggingface.co/Wespeaker/wespeaker-voxceleb-resnet34/resolve/main/voxceleb_resnet34.onnx' -o /tmp/otomekairo-original-wespeaker.onnx
.venv/bin/python scripts/analyze_speaker_recognition.py --baseline-model /tmp/otomekairo-original-wespeaker.onnx --output /tmp/speaker-analysis.json
```

公式前処理との比較には、サーバ用venvへ追加せず一時ディレクトリに参照用の依存を入れる。

```bash
.venv/bin/python -m pip install --target /tmp/otomekairo-audio-reference --index-url https://download.pytorch.org/whl/cpu 'torch==2.5.1+cpu' 'torchaudio==2.5.1+cpu'
curl -fL 'https://github.com/k2-fsa/sherpa-onnx/releases/download/speaker-recongition-models/3dspeaker_speech_eres2netv2_sv_zh-cn_16k-common.onnx' -o /tmp/otomekairo-eres2netv2.onnx
.venv/bin/python scripts/analyze_speaker_recognition.py --baseline-model /tmp/otomekairo-original-wespeaker.onnx --reference-path /tmp/otomekairo-audio-reference --candidate-model /tmp/otomekairo-eres2netv2.onnx --output /tmp/speaker-candidate-analysis.json
```

比較に用いた環境はPython 3.12、NumPy 2.5.1、ONNX Runtime 1.28.0、kaldi-native-fbank 1.22.3、参照用PyTorch/torchaudio 2.5.1 CPU版。
参照依存と候補ONNXは一時ディレクトリに置き、本番の依存定義・同梱モデルは変更していない。

通常検証は`.venv/bin/python -m pytest tests`を実行し、1109件・304 subtestsが通過した（既存warning 1件）。
調査記録のローカルリンク、JSONと比較表の件数、`git diff --check`も確認した。
